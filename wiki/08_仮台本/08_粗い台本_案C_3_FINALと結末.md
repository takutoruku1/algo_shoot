## 書式

- `(who, "text", "face")`。who: 0 あなた（送信された下書き）／1 ミナ／2 レイ・あかり・こはる／3 システム表示／4 投稿。
- ミナの語り（現行 Final.cs／Epilogue.cs の話者 `"地"`）は who=1 のまま `// 語り` を添える。第三者の地の文は置かない。
- `// ―― 下書き選択 ――` 行に全候補。選ばれた例を1行だけ書き、分岐の受けは箇条書き。
- `【初】`＝最初に散らした言葉、`【終】`＝最後に送った言葉、`【散】`＝散った言葉（件数＋実文字列）、`【名】`＝命名ルート、`【迷】`＝迷い秒数。実文字列が入る箇所はプレースホルダで書き、例文は括弧で1つだけ添える。
- `（未承認）` を見出しに付けた場面は下書き段階で、実装には入れない（承認ゲート）。現在は **E5b 見上げる／歩く**（2026-09-07 ユーザー決定。旧「星空」を歩行と一続きにし、さらに順を反転して夜→朝で終える形に改稿）のみ。
- 現行から無変更の要素は「現行維持」とだけ書き、行は写さない。F2 の RECLOSE・カットインに少年言及がないことは現行台本で照合済み。E7 の三人の3行は 12 のスタッフロール投稿に差し替えた（現行維持ではない）。
- `{P2秒}`＝P2 で言った迷い秒数（丸めた実測値）、`{n}`＝送信文字列の文字数など補助観測の差し込み。固定の「三秒」は例文にだけ残す。

### E5b 見上げる／歩く（想定18行・未承認）

**先に見上げ、そのあと歩く。** 四人が夜空を見上げてミナが語り、そこから**夜 → 明け方**へ歩いていく。三人は見上げる場面までに一人ずつ加わっており（面の順＝あかり→こはる→レイ）、最後にミナが四人目として並ぶ。姿はデフォルメ（自機 MINA と同じ頭身）。音は**オルゴール**。

**この順にした利点** — 既存のエピローグは明け方から始まる作りで、昼から始めると 明け方 → 昼 → 夜 → 明け方 と前後が破綻していた。夜から始めて朝で終わらせれば、**E5b の終わりの明け方がそのまま E6 の明け方**になり、時間が一本で繋がる。別の日として切る必要も、明け方の意味づけを捨てる必要も無くなる。

合流の一言の作りかた——加わる瞬間だけ、その人が**「送れるようになった一言」**を一つ置く。名前で呼び合わない、説教しない、礼を言わせない（礼は F2 の返礼で済んでいる）。三人が道中で**打って消していた一行の、その後**として置き、既存の改心・F2 の返礼・E7 のスタッフロール投稿とは**文言を重ねない**。三人はミナに向かって言うのではなく、**誰にともなく言う**（宛先を作らないことで「送れるようになった」だけが残る）。ミナは受けない。数えるだけ。

ミナが四人目に並ぶ理由——三人は救われた側、ミナは救った側だが、F4 で**ミナ自身も救われている**（あなたが最初に散らした言葉が返ってきた）。だから同列に並べる。ただしミナには**それを言わせない**（「わたくしも救われました」は説明台詞）。ミナがやるのは「歩数を数えていたら、四人になった」という**観測の報告**だけで、並んだ意味は絵が言う。

憲法の守り方——「星の数だけ悩みがある」は言わせない。ミナが言うのは**数えられるものだけ**と、**数えられないという申告**。背景は満月と雲のある生成画像なので星の実数は出さない。「下書きは本音・投稿は仮初」も説明せず、**光っているもの／光っていないもの**の対比に落とす。話者はミナ（who=1）・三人（who=2）・語り（who=3）で、**下書き選択は置かない**（頂点は E6）。

```csharp

(1, "……ご主人様。今夜は、こちらを。——わたくしの目で、見た空です。", "mina_face"),            // E5 は他人の写真の空。ここで初めて自分の目で見た空を出す。伝聞をやめる一行
```

- 全18行（見上げ10＋歩行8）。長ければ歩行を6行に詰められる（削るのは語り2行＝「四人は、歩きはじめました。」と「誰も、名前を呼びませんでした。」。三人の一言とミナの2行は削らない）。
- **時間の流れ**: 見上げ＝夜（満月と雲）→ 歩行の途中で東が白む → 最終行で明け方 → そのまま E6。E6 が既に明け方なので**繋ぎ目が無い**。
- 三人の一言は**歩き出してから**の合図であって会話ではない。返事を書かない（ミナの「二件目です」だけが唯一の受けで、それも集計）。三人同士も喋らせない。**挨拶の時刻がずれている**（夜明け前に「おはよ」、そのあと「こんにちは」）のは直さない——揃っていないまま並んで歩けることが、この場面の中身。
- 三人が見上げる場面に**既に居る**理由は絵で示す（歩いてきて立ち止まった、の状態から始める）。合流の過程を描かないことで、見上げ10行に説明が入らない。
- 【散】との結線案: 見上げる場面に `── 見えている星 ── {n}（うち {m} 件、拾得済み）` の表示は置かない（件数を二つ並べると集計の説明になる）。拾得済みは「三件でした」の台詞だけが負う。
- 「三件」は三人＝ステージ数の固定値。ここだけ実測ではなく固定でよい。ボス直行など異常時も三件のままにする。
- ミナの「四人分に、なっていました。」は固定文。三人の合流は必ず起きるので分岐を持たせない。
- （検討・未決）「三件でした。」を「三件だけでした。」にすると自嘲が乗る。説教に半歩近づくので、いまは「三件でした。」を採る。

### E5b 演出の指定

- **歩く絵（推奨: 既存立ち絵の1枚揺らし）** — `char/v3/` に横向きの歩行素材は無い（顔・敵・ボスの正面のみで、歩行は akari/koharu/rei/mina のいずれにも無い）。**歩行アニメを四人分描くのは重いので、描かない案を推す**。四人ぶんの**デフォルメ立ち絵1枚ずつ**（横向き・全身・自機 MINA と同じ頭身。ミナは自機スプライトの流用で足りる可能性あり＝要確認）を用意し、コードで
  - 上下 2〜3px の正弦揺らし（位相を人ごとにずらす＝足並みが揃わない）
  - 接地のたびに横 1.05／縦 0.95 の軽い squash（歩幅の錯覚）
  - 足元に楕円の影。昼は短く真下、夕方は長く横へ伸ばし、夜は薄くする（**時間の経過は影が言う**）
  で「歩いて見せる」。交互歩行の2枚は要らない。**新規に要るのは横向きデフォルメ全身 3枚**（あかり／こはる／レイ）で、ミナは自機流用が効かなければ +1枚。
- **空の変化（推奨: 生成画像1枚＋色調と層で昼夕夜）** — 昼・夕・夜の3枚を生成せず、**夜の空（満月と雲・ユーザー決定）を1枚だけ生成**し、昼と夕方はその1枚に色調変換と層で作る。
  - 昼＝空の層を高輝度の水色寄りにモジュレートし、月と星を α0 に落とす。
  - 夕方＝橙〜菫のグラデーションを加算で重ね、月をうっすら出す。雲の色が一番効くので雲の層は分けて生成しておくと安い。
  - 夜＝生成画像そのまま（月・雲・星）。
  この方式なら**新規の生成は空1枚（できれば雲を別レイヤーで2枚）**で済み、遷移が連続する（3枚だと切り替わりが跳ねる）。歩行は横スクロールなので、遠景をゆっくり流すだけで距離も出る。
- **既存の暁との整合（要注意・実装済みの挙動）** — エピローグの bg2 層は `DawnPhase = 4`（`src/Epilogue.cs:35`）で夜→暁へ 2 秒かけて明け、**E4〜E6 はすべて phase 4＝すでに暁**（`src/Epilogue.cs:40`）。E5b が「昼から始まって夜で終わる」と、暁 → 昼 → 夜 →（E6 で暁に戻る）となり前後が破綻する。案は三つ:
  - (a) **E5b を別 phase の独立カットとして切る**（推奨）。ベランダの部屋（bg2 の層）から一度離れ、屋外の歩行を専用の phase で見せて、終わりに部屋へ戻らず E6 の暁へ繋ぐ。E5 の暁の部屋 → E5b の屋外（昼→夜）→ E6 の暁は、**別の日の話**として読める（E5 は「今日」、E5b は「その日」）。歩行1行目の語りを現行の「その日、ミナは、歩いていました。」にしてあるのはこのため（日付を跨いだと明示せず、跨げる余地だけ残す）。
  - (b) `DawnPhase` を 5 に下げ、E4〜E5 を夜のまま／E5b の夜空から E6 で明ける。絵は最も連続するが、**E4 の開示（起動記録）が夜になり、DM も夜になる**。暁＝遺志の継承という現行の意味づけ（`src/Epilogue.cs:35` のコメント）を捨てることになる。
  - (c) 歩行を昼から始めず「夕方 → 夜」の2段にして、E5 の暁からの繋がりを諦めない。ユーザー決定（昼から）に反するので採らない。
- **加わる演出** — 三人は前から歩いてくるのでも、後ろから追いつくのでもよいが、**追いつく側**を推す（救われた三人が自分の足で来た、が絵で出る。ミナが立ち止まって待つ画にならない）。合流の瞬間に時間が一段進む（画面全体の色調が 1.5 秒かけて次の時間帯へ）。歩みは止めない。
- **見上げへの移行** — ミナの「四人分に、なっていました。」で四人が**同時に立ち止まる**。カメラが少し上へパンして、以降は空が画面の大半を占める。四人は画面下に小さくシルエットで残す（背中越し）。以後 10 行は立ち絵を出さない＝**画面には空と四つの小さな背中だけ**。
- **星に触れるか** — **触れない**。ここで操作を与えると E6 の最後の選択（＝頂点）と競合する。
- **拾った三件の星** — 空の星のうち3つだけ、他よりわずかに大きく暖色に灯す（あかり／こはる／レイの色を流用）。「拾えたのは——三件でした」でその3つが一瞬強く光り、すぐ紛れて見分けがつかなくなる。名前もラベルも出さない。生成画像の星ではなく、**上に重ねたコード描画の点3つ**でよい（生成画像の星は数えないので嘘にならない）。
- **音（オルゴール）** — ユーザー決定でオルゴール。実装が一番安いのは**既存曲のオルゴール編曲**で、エピローグ／メニューの主題（`Audio.BgmMenu`＝`res://audio/bgm_menu_mina.ogg`。`src/Audio.cs:971` の `LoadBgmMenu`）を**同じ旋律のオルゴール音色・テンポ落とし**で1本だけ作る。理由は (1) 同じ旋律が「別の音色で戻ってくる」のが最後の一場面として効く（新規曲だと初対面の曲で終わることになる）、(2) 実装は `Audio` に `BgmEpilogueWalk` のロードを1本足して E5b 突入で差し替えるだけで、既存の `Music()` 経路にそのまま乗る（`LoadBgmMenu` と同型のロード関数＋フォールバック1つ）。新規作曲は不要。
  - 流れ: E5b 突入でオルゴールへクロスフェード（2 秒）→ 歩行と見上げの前半を通して継続 → 「…………。」で**完全停止（無音）**→ 残り2行は無音 → E6 の1行目で主題（`BgmMenu`）が原曲の音色で戻る。オルゴール→無音→原曲、で一周する。
  - 現状の `Epilogue._Ready` は `Audio.Instance.Music(Audio.Instance.BgmMenu)` を1回鳴らすだけ（`src/Epilogue.cs:178`）なので、差し替え点は E5b の phase 突入とその明けの2箇所だけ。
- **所要時間** — 18行で、うち1行は `…………。`、歩行中は色調遷移の待ちが入る。**実測 70〜90 秒**（既定の文字送り速度・Z 送り前提）。長ければ歩行を6行に詰めて 60〜75 秒。
