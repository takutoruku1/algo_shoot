# 組み込み計画（v3 の絵と案C の物語）

> **この記事の範囲**: 実装計画。コードは未変更。承認済み仮台本（[05 場面表](05_場面表_案C.md)・[06](06_粗い台本_案C_1_冒頭とあかり.md)〜[08](08_粗い台本_案C_3_FINALと結末.md) 粗い台本・[12 キャラ設定シート v3](12_キャラ設定シートv2_社会人版.md)・[13 絵の発注方針](13_絵の発注方針.md)・[14 絵の進捗 v3](14_絵の進捗_v3.md)、ユーザー承認 2026-09-05）を、既存のコードへどの順で載せるかを書く。台詞の実装は「ユーザー承認済み仮台本（2026-09-05）」を根拠にできる。

## 前提の確認（現行コードとの落差）

| 項目 | 現行 | v3・案C |
|---|---|---|
| 面の順番 | レイ→あかり→こはる（GameManager の Stages 表） | あかり→こはる→レイ |
| 背景 | 一枚絵を横タイル（StageBackground の MidBgPath と BossBgPath） | 四層（L1 遠景／L2 中景／L3 近景／L4 光）。遠景は無彩色で色掛け、光は加算 |
| 立ち絵・敵 | `char/*.png`（旧・420px 焼き込み） | `char/v3/*.png`（720px 立ち絵、360px ちび、本体と部品の分離） |
| 語り手 | 少年＋ミナ | あなた（Hud.LineKind の 0）＋ミナ。少年の立ち絵は使わない |
| 炎上 | あかりクリア後（ShouldBurnAfter） | こはるクリア後（H2） |
| 画面 | 384×216 の内部解像度 | 背景素材は 1280×720。高さ比 0.3 で縮小して敷く |

自機は 36px、道中の敵は 23〜40px、ボスは 52px（BossAkari ほかの BodyDisplayH）。13 の方針ではボス本体は自機の約2倍なので 52 から 72px 相当への引き上げが要る。

## 全体の順番

依存の向きは A → B → C、D は A と B の後、E は D の後、F は独立でいつでも入れられる。

```
(A) 背景の層 ──┬─→ (D) 面の順番 ──→ (E) 台本の実装
(B) 立ち絵と敵 ─┤
(C) ボスの演出 ─┘                     (F) 投稿文集（独立・並行可）
```

C は A と B に依存しないが、D の面入れ替えでボスの実装ファイルを触るため、C を先に終えて D で位置だけ動かす方が衝突が少ない。F は既存の PostBullets と Hud のティッカーに閉じるので、いつ入れてもよい。

### (A) 背景の層システム

触るファイル: StageBackground（拡張）、新設 BgLayers、AkariRoot・KoharuRoot・ReiRoot・Epilogue・TitleMenu・Hub・TrainingRoot。

やること: StageBackground の「1枚絵＋タイル」を「層リスト」に一般化する。層の定義は（path, scrollMul, zIndex, tint, blend, loop）の配列で Root から注入する。既存の MidBgPath と BossBgPath は残し、層リストが空なら旧経路へ落ちる。既存ステージが即死しない。

- 色掛け: L1 は無彩色なので Modulate に面ごとの色を掛ける。WorldGrade の4段階グレーディングと二重掛けにならないよう、L1 の tint は Root が持ち、WorldGrade は従来どおり CanvasModulate 側に残す。
- 加算: L4 は加算ブレンドの子ノードに分けて敷く（FxLayer の AddDraw と同じ作法）。
- スクロール比: L1 0.15、L2 0.45、L3 1.0、L4 0.0（光は動かさない）。既存の BgScroll の位置係数（0.65〜1.45）を全層に乗算で共存させる。
- ボス突入の暗転: EnterBoss で L4 のαを 0 へ 0.8 秒でフェード、L1〜L3 の Modulate を 0.55 倍へ落とす。STAGE3 だけは逆に L4_light_gold を足す。
- 1280×720 の縮小: 高さフィット（216/720 = 0.3）で幅 384 に一致するので、タイルは1枚で足りる。ループさせるのは L3 のみ、L1 と L2 は固定。

リスク: 層が4〜6枚×3面ぶん増える。1280×720 の RGBA を6枚常駐で約 22MB なので許容だが、面ごとに遅延ロードして他面の層は保持しない。Z の空きは -90（背景）〜-70（ScrollFx）の間しかないので、L1 -95、L2 -92、L3 -91、L4 -88 を割り当て、ScrollFx と StageImagery には触れない。

検証: `--shot --shot-name bg_stage1 --shot-at 2,8,20` を `--demo` 併用で撮り、継ぎ目、弾の視認、ボス突入の暗転を見る。規模 M。

### (B) v3 立ち絵と道中の敵・中ボスの差し替え

触るファイル: BossAkari・BossKoharu・BossRei（顔のパス）、EnemySpec（道中の敵）、StageAkari・StageKoharu・StageRei（CameoTheme）、Hud のカットイン表。

やること: パス文字列の差し替えが主。`char/` を `char/v3/` に読み替え、名前が変わったものだけ表で対応させる。

| 用途 | 旧 | v3 |
|---|---|---|
| 立ち絵 | `char/akari_face.png` | `char/v3/akari_face.png`（cry と lit も） |
| カットイン | `char/cutin_akari.png` | `char/v3/cutin_akari.png` |
| 中ボス | `char/enemy_akari_pre.png` | `char/v3/akari_mid.png`（穢れ無しの1枚） |
| 道中の敵 | `char/enemy_akari_desk_pre/post.png` | `char/v3/enemy_akari_desk_pre/post.png` |
| 改心後 | `char/enemy_akari_post.png` | `char/v3/enemy_akari_post.png` |

中ボスの注意: v3 の中ボスは穢れ形態を持たない1枚。CameoTheme は Pre、Cry、Post の3枚を要求するので、当面は3つとも同じパスを入れる。中ボスは 23px 表示なので視認上の損失はほぼない。レイだけは中ボスが中の人（rei_mid）、ボスがガワで、姿が違うのが仕込み。

リスク（当たり判定の中心のずれ）: 本体スプライトは中央揃えの高さフィットなので、幅が変わっても中心は動かないが、絵の重心はずれる。v3 の道中の敵は横長で旧素材より横に広い。BodyRadius は据え置きでよいが、見た目の当たり判定の一致は `--shot` で目視する。

リスク（少年の立ち絵）: 案C に少年はいない。shonen 系の画像を参照する行は (E) で台詞ごと差し替わるので、B の段階では触らない。

検証: `--shot` で各面の会話・道中・中ボスを撮り、旧絵が残っていないか、塗りがちびと揃っているか。規模 S（面ごとに1タスク）。

### (C) ボスの本体＋部品の演出システム

触るファイル: 新設 src/fx/BossParts、Enemy（発射点フックの公開）、BossAkari・BossKoharu・BossRei、config/boss_stats.ini（倍率と部品の値）。

やること: 13 の「ボス形態＝本体とエフェクトの分離」をそのまま実装する。既存の演出層（PanSlamFx の「テクスチャを1枚読んで描画で動かして自滅するノード」、AreaStrike の Art 列挙）に乗せ、当たり判定は持たせない。

- BossParts（新設）: ボス本体の子として1個ぶら下がる。名前と基準点（足元、発射点）を渡すと `char/v3/fx/<name>/*.png` を一括ロードし、後ろの層（本体の Z より1下）、前の層（1上）、加算の層に分けて置く。
- 公転: 待機は各部品を中心のまわりに角速度 0.35〜0.6 rad/s、位相をずらして周回。半径は本体の表示高の 0.6〜0.9 倍。同時に 0.9〜1.06 倍の脈動（周期 2.2〜3.4 秒）と上下 ±2px の漂い。
- 発射: 攻撃開始で予備動作 0.15 秒（発射点へ部品を吸い寄せ）、解放で前方へ 90〜140px/s で流す。本体は待機から攻撃へ差し替え。
- 散り: 被弾で部品を外向きに散らし、0.5 秒で減衰フェード。本体は攻撃から被弾へ、既存の TickSwapAnim の squash を流用。
- 改心の切替: 部品が全部消えてから本体をクロスフェード。レイは crack を出してからガワを落とし、boss_rei_post（中の人・360px）へ。

リスク（表示倍率）: 現行の 52 は焼き込み版の値。v3 の本体はエフェクトを含まないため、同じ 52 だと小さく見える。13 は自機の約2倍＝72px を指定している。boss_stats.ini に body_display_h キーを足して面ごとに調整可能にし、既定を 72 にする。

リスク（攻撃絵の横幅）: あかりの攻撃絵は 639×720、待機は 487×720。高さフィットで中央揃えにすると、腕を伸ばした分だけ絵の重心が横にずれて見える。対策は姿勢ごとの Offset を素材ごとに持つこと。各担当の完了報告にある足元中央と発射点の座標を 13 の表に転記し、BossParts に姿勢ごとのオフセット表を持たせる。判定は本体の BodyRadius のままで動かさない。

検証: `--shot --demo --shot-at 22,26,30` でボス戦の待機・攻撃・被弾を撮り、部品が回っているか、発射点と部品の出所が一致しているか（左右反転後も）、弾と自機が部品に隠れていないか。`--qa --assist --seconds 240` で FPS を見る。規模 L（面ごとに1タスク＋基盤1タスク）。

### (D) 面の順番の入れ替え

触るファイル: GameManager（Stages 表、ShouldBurnAfter、汚染値）、AkariRoot・KoharuRoot・ReiRoot（汚染の開始値と Title）、Hub（カード順は Stages に従うので自動）。

1. GameManager の Stages を あかり → こはる → レイ の順に並べ替え、Title を「STAGE 1 — あかり」等に振り直す。カード順、次の未クリア面、解放判定は全部この配列を読むので、表の並べ替えだけで導線が変わる。
2. 汚染の進行: 現行は各 Root がハードコード。案C は1面目が最も薄く3面目が最も濃い。あかり 0.00→0.18、こはる 0.18→0.45、レイ 0.45→0.80 に振り直す。S3-7 の割り込み（「わたくしの光、二割ほど濁っています」）は 0.80 に対する言い方なので、レイ面の終盤値と台詞を揃える。
3. 炎上の位置: ShouldBurnAfter を こはる に変える。炎上は次の1ダイブだけ効くので、こはる→レイの入りが弱くなる。案C と一致する。
4. セーブの互換: クリア済みは ID の集合なので並べ替えても壊れない。旧セーブで「レイだけクリア済み」の人は、新順では3面目だけクリアの状態になる。ゲームとしては正しく動くが物語の順序は狂う。移行はしない（周回中として扱う）。

リスク: ScrollFx のコメント（「STAGE1 レイ」等）と AkariRoot の「STAGE2」が嘘コメントになる。並べ替えと同じコミットでコメントも直す。boss_stats.ini の見出しも同様。

検証: `--qa --assist --quit --seconds 900` を Prologue から通し、シーン遷移が Akari → Koharu → Rei → Final → Epilogue になるか。ハブのカード順を `--shot`（autoplay なし）で撮る。規模 M。

### (E) 台本の実装

触るファイル: Prologue（P0〜P4）、StageZero（練習）、Hub（H0〜H3・返信）、StageAkari＋BossAkari（S1）、StageKoharu＋BossKoharu（S2）、StageRei＋BossRei（S3）、Final＋BossMina（F1〜F4）、Epilogue（E1〜E6）、ChoiceOverlay（3択への拡張）、GameManager（仕掛けの値）。

やること: 面の台詞は（who, text, face）の配列で既に表データ化されているので、配列の中身を差し替えるだけで入る。順序は 05 場面表のとおり。

- P0〜P4: 現行は「文字の雨、identity、少年との初対面、タイトル」。案C は「文字の雨（414件・四行の英文）、目覚めと最初の言葉（3択）、命名（3択）、タイムライン（3択）」。少年の台詞と立ち絵をすべて落とし、LineKind 0 をあなたの選択に置き換える。3択は ChoiceOverlay の選択肢数を可変にする拡張が要る。
- 練習: 15 項目の実況を落とし、浄化と締めの2行だけにする。既存の phase 番号は触らない。
- ハブ: H0（あかりのカードだけ新着）、H1（初投稿が千超え）、H2（十万＋炎上・引用が八枚）、H3（汚染が限界へ）。返信は既存の返信機構に乗る。
- 面の台詞: 面ごとに3タスク（導入と小話、道中と中ボス、ボスと改心とクリア）。既存の step 構成は案C の場面とほぼ1対1なので、step の構造は変えず配列の中身だけを差し替える。
- 引用の嵐（S3-5b）: 新設の遊び。11 の設計（17枚・3段階・約50秒）を StageRei の新 step として足す。後回し可。
- FINAL とエピローグ: F4 の「最初に散らした言葉が戻ってくる」と E2 の合言葉、E4 の開示が仕掛けの値に依存する。

仕掛けの値（GameManager に足してセーブに載せる）:

| 値 | 型 | 立つ場所 | 使う場所 |
|---|---|---|---|
| 散った言葉 | 文字列の一覧 | P2 P3 P4 と各面の選択で選ばなかったほう | E1「七件、ぜんぶ拾ってあります」 |
| 最初に散らした言葉 | 文字列 | P2 で散った2語のうち上の候補 | F4 の最後の選択、E4 の開示 |
| 命名ルート | 整数 0〜2 | P3 | E3 の四行の英文（1行だけ変わる） |
| 最後に送った言葉 | 文字列 | F4 と E6 | E2 の合言葉の正解 |
| 迷い秒数 | 秒 | P2 の選択にかかった秒 | P2 の受け、E6 の対句 |

保存はキー無しなら既定値の後方互換で足す（既存の pressedQ と同じ作法）。既存の合言葉ゲート（正解 stay）は案C の E2（正解＝最後に送った言葉）に置き換わるので、候補配列も差し替える。

リスク: 台詞の量が多い。1面ぶんで 60〜120 行あるので、夜間の1タスクに1面ぶん全部を積まない。面を3つに割る。

検証: `--qa --assist --quit` で最後まで進むか。`--shot --demo` で会話画面を撮り、顔と話者が合っているか。design-gap で 05〜08 と実装の差分を出す。規模 L。

### (F) 投稿文集の差し込み

触るファイル: PostBullets、Bullet（SetWord まわり）、Hud（ティッカー）、新設 PostPool。

やること: 09 の三層（日常、病みサインあり、本人）をプールとして持ち、PostBullets と Hud のティッカーが層を指定して引く。10 の案A（撃って届ける）を層2に付ける。

- 層付きプール: テーマと層で1件返す。既存の8語ハードコードを置き換え、道中でも投稿弾を流す（現行はボス戦のみ）。
- 病みポストを見つける: 層2は画面に1枚まで、いいね数 0〜3、深夜の時刻、暖白のハロ（祈り弾のハロを流用）、落下 0.8 倍。撃つと祈り弾と同じ経路で拾える。やさしさ +0.02、スコア +15。
- リスク: 層2を撃つために自機がレーンへ入るので被弾が増える。まず層1と層3だけ差し替えて、案A の遊びは別タスクにする。

検証: `--qa` で弾数の上限と FPS。層2が画面に2枚出ていないか。規模 M。

## 指揮官の決定（2026-09-05）

1. 旧資産は残す。非正典の試作（StageW0 など）がまだ参照している。
2. ボスの表示倍率は既定 72 で入れ、`--shot` を見て 64 前後へ落とすかを決める。ini で変えられるようにする。
3. 攻撃絵のオフセットは、各担当の完了報告にある足元中央と発射点の座標を 13 の表に転記して使う。再トリムはしない。
4. 引用の嵐は後回し（P3）。台詞だけ先に入れ、遊びは後から差す。
5. 旧セーブは移行しない（周回中として扱う）。
6. 少年と非正典（BossHikage、StageW0）はこの計画では触らない。

## 最初の1週間で動く状態

上から順に消化すると、1週間（5晩、10〜15件）で次まで届く見込み。

- 背景: 三面とも bg2 の四層で敷かれ、色掛けと加算の光が乗り、ボス突入で暗くなる。タイトル・ハブ・練習・エピローグはまだ旧背景。
- 立ち絵と敵: 三人の立ち絵・カットイン・道中の敵・中ボスが v3 に差し替わる。ボスの本体はまだ旧のまま（部品の基盤は入っているが配線は1面ぶん程度）。
- 面の順番: あかり→こはる→レイ に入れ替わり、汚染の進行と炎上の位置が新順に合う。
- 台詞: まだ旧台本（少年が出る）。ここは1週目には届かない。

つまり1週目の終わりに「見た目は v3、物語は旧」の状態になる。絵の作業と物語の作業を独立に進められる設計なので、これは意図した中間状態。
