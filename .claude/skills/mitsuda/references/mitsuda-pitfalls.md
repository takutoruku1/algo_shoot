# 光田康典エージェント 自己レビュー・ゲート（落とし穴）

設計・実装したドラフトを**出す前に**必ず通す。1つでも引っかかったら直してから提示する。
`/maeda` の pitfalls、`/sakurai` の §7「やってはいけない設計」の音版。

---

## P1. 鳴らしすぎ（余白の喪失）
- **症状**: 全イベントに音を盛り、無音の瞬間が無い。常時BGM＋全SEで耳が飽和。
- **なぜ悪い**: 何も際立たない。決定打・挿入歌・浄化の重みが消える（style §7）。テンポの聴覚版が死ぬ（`/sakurai` §3）。
- **直し**: 「鳴らさない」を設計に入れる。決定打の直前は無音。雑多なイベント（敵弾発射など高頻度）は音量を下げる/間引く/まとめる。挿入歌・決定打音は**一点投入**。

## P2. 重要警告音が埋もれる
- **症状**: 被弾・残機減・ボス段階移行が、弾幕の発射音やBGMに紛れて聞こえない。
- **なぜ悪い**: 音の第一機能＝情報（style §5）が果たせない。プレイヤーが「いつ食らったか」を耳で取れない。
- **直し**: 警告音に最優先・ダッキングを設計（`implementation.md` §E）。被弾音は何があっても抜けて聞こえる音色・帯域・音量に。

## P3. 画と音のズレ
- **症状**: 撃破/浄化の演出（`FxLayer.*`）と音が別タイミング、または画だけ・音だけ。
- **なぜ悪い**: 手応えの三点（止め・音・光）が揃わず快感が死ぬ（style §4／`/sakurai` §4）。
- **直し**: SEは必ず既存の `FxLayer` 呼び出しと**同フレーム**で発火。`sound-map.md` の「同期する視覚フック」列を埋めてから実装。

## P4. 世界観に反する音（撃破＝破壊音だけ）★
- **症状**: 敵浄化・パネル砕けを、爽快なだけの「破壊音」で処理する。
- **なぜ悪い**: このゲームの根幹「**浄化＝倒すでなく届ける・救う**」と齟齬。撃って気持ちいいだけだと、麻枝の物語（赦し・救出）と音が喧嘩する。
- **直し**: 砕け／浄化は、アタックの後に**温かい余韻**（ベル・パッド・`KindnessMote` と同期）。「壊した」でなく「解けた・届いた」と聞こえる音に。Final/改心は旋律で赦しを描く。

## P5. 主題の不在 or 濫用
- **症状**: シーンごとに無関係な曲を並べた（主題が無い）／逆に毎シーン主題を頭から鳴らして聞き飽きる。
- **なぜ悪い**: 主題と変奏（style §1）が作品の記憶を作る心臓。無いと散漫、濫用すると陳腐。
- **直し**: メインモチーフを1本決め、各シーンは**変奏**（調・編成・密度の差）で繋ぐ。普段は断片・通奏低音に沈め、「ここぞ」で立てる。Prologue 仕込み→Final/Epilogue 回収（`/maeda` Acrostic と共有）。

## P6. 挿入歌・決定打音の乱発
- **症状**: ボーカル挿入歌や「泣かせの音」を何度も使う。
- **なぜ悪い**: 希少性が重みを生む（style §7／`/maeda` music§4）。乱発した瞬間に安くなる。
- **直し**: 挿入歌は作中**一度だけ**、最大の山（Final 決定打）に。直前を無音に。`/maeda` のト書きと行単位で対応。

## P7. ブツ切り遷移・ループの継ぎ目
- **症状**: シーンが変わると曲が突然切れて次が始まる。道中曲のループ境界が露骨。
- **なぜ悪い**: 没入とテンポを壊す（style §6・§9）。STGは長時間・周回で聴くので継ぎ目が命取り。
- **直し**: クロスフェード（`implementation.md` §C）。イントロ＋ループ本体、2周目イントロ省略。ループ点を実際に聴いて詰める。

## P8. アダプティブの作り違い（連続と離散の取り違え）
- **症状**: 汚染ゲージ（連続値）でいきなり曲を切り替える／段階移行（離散）をフィルタでぼかすだけ。
- **なぜ悪い**: 連続値の急な分岐はガクつき、離散の見せ場がフィルタだと弱い（style §6）。
- **直し**: **連続値＝フィルタ/音量（LowPass・濁りパッド）**、**離散イベント＝レイヤー追加・曲分岐**。視覚の濁り曲線（`Player.cs` Tint）と音を一致させる。

## P9. デモ/QA を壊す・テンポを落とす
- **症状**: 自動プレイ（`--qa`/`--demo`）で音処理が走り、高速実行や無音前提が壊れる。
- **なぜ悪い**: `QaPilot`/`DemoPilot` は無音・高速で回る設計。SEプール/エフェクトが負荷やログを乱す。
- **直し**: `Audio.Muted` を QA で立て、SEは即 return。デモ収録時のみ鳴らす分岐（`implementation.md` §F）。

## P10. 実音源を偽る／机上で語る
- **症状**: 実際の録音楽曲が無いのに「作曲した」と報告する。実際に聴かずに音を語る。
- **なぜ悪い**: この環境に音声生成は無い。誇張は信頼を壊す。机上の音評は外す（style §12）。
- **直し**: **設計と結線はできる／実音源は外部調達が要る**を正直に言う。暫定音で結線し差し替えポイントを明示。実装後は `play-game`/`demo-video` で**実際に聴いて**確かめてから完了と言う。

## 通過確認（提示前にこの行を自分に問う）
- [ ] P1 無音・余白を作ったか（全部に音を盛っていないか）
- [ ] P2 被弾等の警告音が最優先で埋もれないか
- [ ] P3 SEは `FxLayer.*` と同フレームか（画と音が一致）
- [ ] P4 浄化/砕けが「届ける救う」の音か（破壊音だけでないか）★
- [ ] P5 主題を1本立て、各曲は変奏で繋いだか（無し/濫用でないか）
- [ ] P6 挿入歌・決定打音は一点投入か
- [ ] P7 遷移はクロスフェード、ループ継ぎ目を詰めたか
- [ ] P8 連続=フィルタ／離散=レイヤー・分岐で作ったか
- [ ] P9 QA は Muted、デモ収録のみ鳴らすか
- [ ] P10 実音源の要否を正直に切り分け、実際に聴いて確かめたか
