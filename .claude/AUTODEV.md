# AUTODEV — 夜間クラウド routine の作業手順書

このファイルは `/schedule` で登録した routine が毎回読む手順書。routine のプロンプトは短く保ち、実際の手順はここを正本にする（手順を変えたいときは routine を作り直さず、このファイルを編集すればよい）。

## 前提

- 作業ブランチは `auto/dev`。`main` には直接コミットしない。
- **1タスク = 1コミット。** 1回の実行では、時間の許す限り**複数タスクを順に**消化してよい（ステップ2〜7のループ）。ただし複数タスクを1コミットにまとめない。
- ビルドが通らないものはコミットしない。
- **時間予算 = 3時間**（JST 3:00 開始 → 6:00 まで）。これを超えないよう自分で打ち切る。

## 手順

### 0. 開始時刻を記録する

ループの各周で残り時間を判断するために、最初に基準時刻を取る。

```bash
date -u +%s > /tmp/autodev_start   # 開始時刻（UNIX秒）
date -u                            # ログ用に人間可読でも出しておく
```

以降、残り時間はこう測る（**予算10800秒 = 3時間**）:

```bash
echo $(( 10800 - ($(date -u +%s) - $(cat /tmp/autodev_start)) ))   # 残り秒数
```

### 1. 準備

```bash
git fetch origin
git checkout -B auto/dev origin/main   # main の最新から作り直す（PR がマージ済みでも未マージでも main 基準で始める）
```

> 既存の `auto/dev` に未マージPRがある場合は、`origin/auto/dev` を checkout して続きから積む。
> 判断: `gh pr list --head auto/dev --state open` が空なら main 基準、あれば auto/dev 基準。

### ★ ここから 2〜7 をループする（1周 = 1タスク）

各周の**先頭**で必ず残り時間を測り、次のいずれかに当たったらループを抜けて **8. 仕上げ** へ進む:

- **残り 1200秒（20分）未満** — 次のタスクを始めるには足りない。中途半端に着手しない
- **TODO が空** — ただし残り時間が 3600秒（1時間）以上あるなら、抜ける前に **★★ 監査モード** へ（下記）
- **ビルド失敗や BLOCKED が3回連続** — 何か根本的におかしいので、それ以上回さず人間に委ねる

打ち切った理由は最後の報告に必ず書くこと。

### ★★ 監査モード（TODO が空になったときだけ）

キューが枯れたら、**自分で「足りないこと」を見つけて補充する**。1回の実行で監査は**1度だけ**（補充したキューをその実行で消化し、また空になっても再監査はしない）。

`game-designer` / `engineer` / `scenario` / `qa` の4ワーカーを **1メッセージ内で並列に**投げ、それぞれの観点で洗い出させる:

| ワーカー | 観点 |
|---|---|
| `game-designer` | リスクとリターン・手触り・視認性・テンポ・親切設計。実装値に紐づけて具体改善を出す |
| `engineer` | 死にコード・嘘コメント・警告・実装同士の矛盾・壊れている経路 |
| `scenario` | `docs/` の正典と実装セリフの乖離、伏線の仕込み/回収漏れ、人称・語彙の揺れ |
| `qa` | ヘッドレス自動プレイでの当たり判定・進行不能・例外・弾リーク・FPS |

各ワーカーには次を必ず指示する:

- **根拠を `ファイル:行` で示すこと。** 「あったら良さそう」ではなく「実装がこうなっている」「正典とこう違う」を書く
- **既に実装済みのものを提案しないこと**（`src/` を grep してから出す）
- **1ワーカーあたり最大5件**まで。実害の大きい順

#### 積んでよいもの / いけないもの

**自動で TODO に積んでよい**:
- 不具合・バグ・壊れている経路
- 正典（`docs/`）と実装の乖離
- 品質向上（手触り・視認性・テンポ・バランス・可読性・警告解消）

**TODO に積んではいけない＝ `## BLOCKED` に「要ユーザー判断」付きで置く**:
- **新機能・新モード・新規コンテンツの提案**（例: 新しいゲームモード、新キャラ、マルチエンディング）
- ゲームの方向性を変える設計変更
- 大規模リファクタ（影響範囲が広く、判断が要るもの）
- 外部リソースが要るもの（API キー、素材調達、権利確認）

判断に迷ったら **BLOCKED 側に倒す**。勝手に作らない。

#### 積むときのルール

- 合計 **最大15件**まで（消化が追いつかないので欲張らない）
- 既存の `## TODO` / `## BLOCKED` / `## DONE` と**重複していないか確認**してから積む
- 優先度 `(P1)`〜`(P3)` と担当ワーカーを付け、受入条件に**根拠のファイル:行**を含める
- 積んだらコミットする（`auto: 監査で N 件をキューに追加`）

補充が終わったら**ループの先頭に戻って**、積んだタスクを普通に消化していく。

### 2. タスクを1つ取る

`DEV_QUEUE.md` の `## TODO` 最上段の1件を読む。空ならループを抜けて **8. 仕上げ** へ。

取ったタスクを `## WIP` へ移し、この時点で一度コミットする（多重着手防止）。

> **1周で扱うのは1タスクだけ。** 先読みして複数まとめて着手しない。

### 3. 「もう実装済みでないか」を先に確かめる

**キューは古びる。** 実装する前に、そのタスクが既に done でないか必ず確認すること（過去に #22/#27/#11 が実装済みのまま積まれていた実績あり）。

- `src/` を grep して該当機能の実体があるか見る（`docs/タスク管理.md` の状態欄は**信用しない**。実コードが正）
- `git log --oneline -S"<キーワード>"` で導入コミットを探す

実装済みだった場合は、**実装せず** `## DONE` へ「(完了 済) 根拠=ファイル:行 か コミットハッシュ」付きで移し、次のタスクへ進む。これは空振りではなく正しい仕事。

### 4. 実装する

タスク行の担当ワーカー（`engineer` / `qa` / `artist` / `scenario` / `composer` / `game-designer`）を Agent ツールの `subagent_type` に指定して振る。受入条件（`|` 以降）をそのままワーカーへの指示に含める。

- 仕様が曖昧で判断が割れる → 実装せず `## BLOCKED` へ理由付きで移し、次のタスクへ。
- 15分相当を超えそうな規模 → 同じく BLOCKED へ（人間に分割してもらう）。

### 5. 検証する

```bash
dotnet build algo_shoot.sln
```

通らなければ `git checkout -- .` で変更を捨て、そのタスクを BLOCKED（理由=ビルド失敗の内容）へ。

QA系タスクなら `qa-autoplay` skill も回す。

### 6. キューと進捗を更新する

- 完了タスクを `## WIP` から `## DONE` の先頭へ、`(完了 YYYY-MM-DD)` を付けて移動。
```bash
node tools/progress.mjs    # PROGRESS.md と docs/progress.json を再生成
node tools/dashboard.mjs   # docs/dashboard.html を再生成
```

### 7. コミットする（このタスク単体で）

```bash
git add -A
git commit -m "auto: <タスク名の要約>"
```

**ここで push はしない。** コミットしたら **2. に戻ってループの次の周へ**（先頭で残り時間の判定を忘れずに）。

### ★ ループを抜けたら以降へ

### 8. 仕上げ — push して PR にする

ループ中に積んだコミットをまとめて1回だけ push する。

```bash
git push -u origin auto/dev
```

PR がまだ無ければ作る（あれば push だけでよい）:

```bash
gh pr list --head auto/dev --state open   # 空なら↓
gh pr create --base main --head auto/dev \
  --title "auto: 夜間自動開発の積み上げ" \
  --body "$(cat PROGRESS.md)"
```

PR が既にあるなら本文を更新: `gh pr edit --body "$(cat PROGRESS.md)"`

### 9. 報告

最後に簡潔に報告する:

- **消化したタスク一覧**（1行ずつ。完了 / BLOCKED / 実装済みだった、の別を書く）
- **ビルド結果**
- **打ち切った理由**（時間切れ / キューが空 / 連続失敗）と使った時間
- **残りタスク数**
