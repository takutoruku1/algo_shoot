#### 【2】三本の回想フィルムが第三者ナレーション ─ 方針の正面違反

**file**: `src/AkariStoryFilm.cs:8,14,20,31,35` / `src/KoharuStoryFilm.cs:12,18,23,27` / `src/ReiStoryFilm.cs:8,11,15,20`

**問題**: 話者名が空＝地の文で、**過去形の第三者視点**。memory [[narration-rule]]「第三者の語り手は存在しない。ナレは全部ミナの肉声」に真正面から反する。しかも同じファイル群の `MinaStoryFilm.cs:8` は正しく「わたくしは手のひらを開きました」と**ミナの声**で書かれており、**作品内で語りの規則が二重になっている**のが最悪。プレイヤーは同じ見た目のフィルムで、ある時は神視点、ある時はミナ視点を読まされる。

**直し案**: 地の文を「ミナが見ている」文体へ統一する。敬体＋観測の語彙に寄せるだけでよい。

```csharp
// 現行 → 直し案
"同じ日に入社して、同じ総務に配属された。向かいの席は、西野くんだった。"
→ "同じ日に入った二人が、向かい合わせの席に。……八年前の春だ、と記録にあります。"

"人が辞めるたび、残った人の仕事が増えた。向かいの席は同じでも、話す時間は減っていった。"
→ "人が辞けるたび、残った机の上のものが増えていきます。席は、同じまま。……会話だけが、減っていきました。"

"電話が鳴った。受話器を取っている間に、向かいの席のモニタが消えた。"
→ "電話が鳴りました。受話器を取っている間に——向かいのモニタが、消えます。"
```

**理由**: 語りをミナに寄せると、回想が「ミナが下書きから読み取った記録」になり、**能力の描写そのもの**に変わる。第三者ナレは「作者が説明している」に見え、show-don't-tell も同時に破っている。ミナの声にすれば、同じ情報が「観測」として提示されるので説明臭が消える。

> ただしコストは大きい（三本で約120行）。全面改稿が重ければ、**最低でも各フィルムの冒頭1行だけ**ミナの声にして「これはわたくしが読んだ記録です」と枠を宣言し、以降を「読み上げ」として成立させる折衷案がある。

#### 【3】プロローグのミナに「ふふ」と自嘲が既にある ─ 感情アークの前借り

```csharp
"それと、ご報告を。わたくしの心拍、七十二だそうです。……機械のくせに、ですね。"
```

#### 【6】三面の改心が同一フォーマット ─ 三度目に飽きる

**file**: `src/BossAkari.cs:89-99` / `src/BossKoharu.cs:136-148` / `src/BossRei.cs:117-126`

**現行の型**（三面とも同じ）

#### 【8】こはるの改心に一行多い ─ 決定打の直後を汚している


**問題**: lines「仕上げの一手順 4. 直後に余白を置いて、読者が泣く時間を作る」に反する。**決定打の直後に説明的な補足**が入っている。「しなくていいのです」は、こはるの救済の芯（＝推し活まで採点しなくていい）として内容は正しいが、**位置が悪い**。無音で置いた決定打の余韻を、次の行が即座に埋めてしまう。

**理由**: 「……ほんとに？」だけで一度切ると、こはるが**確かめに来る**間が生まれる。そこへミナが「約束はしなくていい」と返し、こはるが自分から「また見に行っていいのかな」と言う。現行の一続きの台詞を二つに割るだけで、**こはるが自分で選び直した**形になる（pitfalls P4：救う相手を器にしない）。

4. **【16】レイ面の「混ぜてあります」を削除** — 1行削るだけで作品最良の呼応が生まれる
5. **【6】レイの改心の順序を反転** — 三面目の既視感を消す
