## 0. 設計の中心アイデア — 「二層のゴール」
現行は**伏線回収型**で、明確なゴールが無く意味反転だけで完成する。一方ユーザーは「ゴールを目指す」感触が欲しい。
矛盾を、**表のゴール（プレイヤーが意識して目指す建前）／裏のゴール（最後に気づく真実）**の二層で解決する。撃って解決しない・気づかせる原則を一切壊さない。

| | 表のゴール（起で提示・常時可視） | 裏のゴール（結で判明・説明しない） |
|---|---|---|
| 内容 | **「濁った3つの心を浄化し、Xの闇を成敗する」** | 少年が、死ぬ前に大切な3人へ"別れ"を正体を隠して届ける |
| 担い手 | プレイヤー＝ミナ（自機）が目指す | 少年が最初から遂げていた |
| 可視化 | 浄化カウント（3つ）＋ミナの汚染ゲージ（対の代償） | フォロー欄・鍵アカ・頭文字で回収 |
| 機能 | 起承転結の「目標」になる | 1周目の建前を別れの準備へ反転させる |

**効果**: プレイヤーは「3人を救う」ゴールに向かって進む（起承転結が成立）。だが救うほどミナが濁る（リスクとリターン＝緊張）。結末で「本当のゴールは別れだった」と反転 → 既存の主題「届けられなかった想いは、なかったことにはならない」がそのまま生きる。

> **意思決定（A）= 確定（2026-06-19）: 「控えめ」**。タイムライン端に小さく「浄化 ◯/3」＋汚染ゲージ。目標は伝えるが情緒を削がない。麻枝の「気づかせる」原則と整合。HUD実装は systems へその粒度で申し送り。

## 1. #13 起承転結マップ（一本道のまま目標を通す）

```
起｜PROLOGUE＋STAGE1道中  … MINA起動・機能・目的（表ゴール）提示／主従漫才で“好きにさせる”
承｜STAGE1ボス〜STAGE2     … 浄化を重ねる＝前進。掛け合いの日常。汚染が静かに進む（違和感の蓄積）
転｜STAGE2末〜STAGE3〜FINAL … 少年の異変／ミナの「知ってるんですか?」／汚染暴走。表ゴールが崩れ裏ゴールが滲む
結｜EPILOGUE              … 少年はもう来ない＝死。裏ゴールが完了済みと判明。名前の反転・遺志の継承
```

- **目標の前進感**は「浄化 1→2→3」の達成で出す。**代償**は汚染ゲージの濁り進行で出す（既存4-bをそのまま目標の対カウンターに使う）。
- 各ステージ末に**短い「帰還＝日常」ビート**を必ず置く（後述#3）。前進の区切り＋感情移入＋汚染の可視化を同時に担う。
- 設計書の変更点: §5物語フローマップに「表ゴール提示（起）／浄化カウントの前進／汚染の対カウンター」を明記。各ステージ間に「帰還ビート」を正式な実装単位として追加。

## 2. #3 感情移入フェーズ（ビート2「日常の構築」を厚く）

現行は漫才テンポは良いが、**“無目的な日常”の総量が少ない**＝喪失時の落差が稼げない。以下を増設。

### 2-1. 反復儀式（ログインの合言葉）を起から仕込む ★最重要
- 少年が**毎回ダイブ前に必ず言う一言**を定型化する。これを EPILOGUE の鍵アカPW／"Never leave, okay?"（伏線①⑤）と接続。
- **確定（2026-06-19）: 合言葉＝英単語1語「Stay.」／鍵アカPW＝`stay`**。少年がダイブ前にキザに「Stay.」と言う（＝「いなくなるな／そばにいろ」）。Acrostic「Never leave, okay?」と直結。
  - 反転: 「stay」と命じた少年こそが stay できず逝き、ミナが stay し続ける（名前の約束の成就）。鍵アカでは MINA／誕生日／天才 は弾かれ、`stay` で開く。
  - **実装済**: P-00 PROLOGUE 末に初出を追加（`src/Prologue.cs`、軽い掛け合いで仕込み・口癖「アホですね」で締め）。
- 効果: frontcraft「定位置・口癖」＋casebook CARD1（反復モチーフの反転）＋lines§5（日常語の再来）。**結で同じ言葉が"自分への言葉ではなかった"と反転**（既存P-EPの構造をそのまま強化）。
- 残作業: 各ステージ「ダイブ前」に「Stay.」反復を1行ずつ／P-EPの鍵アカPWを `stay` に確定差し替え（未確定項目の解消）。

### 2-2. 帰還ビート（無目的な日常の小箱）を各ステージ末に増設
- 浄化後、次へ行く前に**物語を進めない雑談**を2〜4往復だけ置く（既存P-01c/P-02cを拡張、STAGE3後にも追加）。
- 中身は世界観の小話・軽口・ミナの好奇心（現実世界を見られないミナが少年経由で外を想像する等）。frontcraft「無目的な会話＝日常の尊さ」。
- これは Epic A（道中ザコ＋小話）の受け皿にもなる（道中で世界観、帰還で関係性）。

### 2-3. ミナ側の「好きにさせ」— ミナにも欲を持たせる
- ミナの口調（毒舌敬語ツンデレ）は確立済み。加えて**ミナ固有の小さな願い**を一つ置く（例: 「いつか現実の空を見てみたい」）。これは叶わない（視点の断絶を保つ＝原則厳守）＝静かな代償。
- pitfall P2回避: プレイヤー＝ミナに主体性。「汚染を引き受けてでも3人を救う」選択を**ミナ自身の意志**として一行描く。

## 3. #14 チュートリアルの「起」（STAGE1道中でMINAの機能と目的を伝える）

STAGE1道中＝**操作チュートリアル＝物語の起**を兼ねる。教える順に物語を乗せる。

| 道中の進行 | 教える操作 | 乗せる物語（起） |
|---|---|---|
| ダイブ直後 | 移動 | ミナ＝少年が作ったAI、心象世界に潜れる（機能） |
| 最初の言葉弾 | ショット＝祓う | 「飛んでくるのは"言葉"。本人じゃない。撃って祓える」（既存P-01b流用） |
| 弾が途切れた間 | （無操作の間） | **なぜミナを作ったか**を軽口で匂わせる（建前＝闇成敗／本音は伏せる）→ 合言葉の初披露 |
| ボス手前 | 倒さず奥へ届ける | 「倒すんじゃない。奥の"本人"に光を届ける」（既存流用＝撃って解決しない原則の教示） |

- pitfall P3回避: ミナの機能（潜る/祓う/届ける/汚染する）を**ここで明示したルールから最後までブレさせない**。
- 設計書の変更点: P-01a/bに「機能説明＝チュートリアル」の道中セリフを正式追加。Epic A の道中ザコ実装とセットで作る。

## 4. #12 各ボスの主張 → 弾幕・技・演出（アーキタイプ翻訳）

3ボスは**全員が「未練を抱えた知人の心象」**（TYPE E系）。だが pitfall P1（ワンパターン回避）のため、**未練の質を3方向に振り分け**、弾幕と演出で別物に見せる。

| | レイ（STAGE1） | あかり（STAGE2） | こはる（STAGE3） |
|---|---|---|---|
| 主張（未練） | 認められたい（承認の渇き） | 言えなかった想い（名前で呼ばれたい） | 祈りは無駄じゃない（無力感） |
| 寄せる型 | E＋承認 | E＋**B（名前モチーフ）** | E＋**C（変えられぬ宿命=兄の余命）** |
| 弾幕モチーフ | 「順位/数字」弾。無限の"2位"が降り、1位は白飛びで撃てない（届かぬ頂点） | 言いかけて弾ける白い吹き出し弾（「す——」で爆ぜる）。雨の縦弾 | 「むだだよ」弾を**下方向**へ＝食卓に落ちる祈り。冷めゆく料理 |
| 技（主張の体現） | プレイヤーが避け続けると「また逃げる」と弾が増す＝戦ってもらえない渇きが攻撃化 | 名前を伏せる＝弾が「キミ」表記。中継（ミナの声）を当てた弾だけ和らぐ | 祈り（料理）が弾になり自分へ返る＝他責の構造。届けると下弾が止む |
| 解決の核（既存） | 「価値ある好敵手だった」と認める | 「想いは罪じゃない／届いている」 | 「祈りは届いていた／命を支えた」 |
| 演出の反転 | 浄化で1位の白飛びに色がつき「2位にも価値」 | 黒板の「あたしのせい」が「ありがとう」へ | 空席の箸に湯気が戻る／投稿が「一緒に食べる」へ |

- **#20（小春の下ショットを活かす）と直結**: こはるの「下方向の祈り弾」を、プレイヤーの下ショットで受け止める/打ち返す設計にすれば、機構と主張が一致（systems と連携）。
- pitfall P4厳守: 各ボスの救済で**そのボス自身が何を望むか**を必ず一拍描く（少年の別れの道具にしない）。既存テキストは満たしているので、増設分も同基準で書く。
- 設計書の変更点: §3キャラ表に「弾幕モチーフ／技」列を追加。§6各BOSSパートに演出ト書きを追補。

## 5. #23 エンディング／スタッフロール方針

- **方針: 引き算を維持**（設計書§7: 過剰なBGM・モノローグを避ける）。
- **スタッフロール＝タイムライン演出**に統一（Epic G #27/#11 のSNS化と一本化）。流れる投稿＝**救った人々の"その後"の投稿**（レイ「次こそ勝つ」／あかり「ばか／あたしも」／こはる「ちゃんと食べてね」＝既存の変化後投稿）がゆっくり上る中をクレジットが流れる。
- 最後にミナのDM「ちゃんと食べていますか?」（伏線④回収）で締め、**#21（エンディング後タイトルへ復帰）**に接続。
- 挿入歌は**FINALの決定打にのみ一点投入**（music§4）。EN は無音寄りの余韻（lines仕上げ）。
- 設計書の変更点: §7に「スタッフロール＝タイムライン／その後の投稿」を明記。EN→Title遷移を追記。
