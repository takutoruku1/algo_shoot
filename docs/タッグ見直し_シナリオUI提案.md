# タッグ見直し提案 — MINA シナリオ＆UI

桜井政博エージェント（UI/ゲームデザイン）× 麻枝准エージェント（シナリオ）のタッグによる見直し提案書。
各自が自分の思想/作風ドキュメントと実装値を読み込んだ上で独立に批評し、さらに互いの「UI×シナリオの境界」をすり合わせた統合版。
**この文書は提案のみ。コードは未変更。**

シーンチェーン: `Prologue → Rei → Akari → Koharu → (Mina) → Final → Epilogue`

---

## 0. 総評：骨は正しい。足りないのは「見せる」と「緩み」

両者の診断が一致した核心：

- **桜井**：仕組みは作り込まれているのに**画面に出ていない**。最大例が「やさしさゲージ（Kindness/Overload）」— `GameManager.cs:351-398` に実装され手触りも激変するのに、`Hud.cs` に描画が一行も無い。このゲーム最大のリスク→リターンが不可視。
- **麻枝**：伏線の骨格（Acrostic `M/I/N/A` の仕込み→回収、善行＝世界の秘密の反転、3ボスのアーキタイプ分け）は完成度が高い。足りないのは**前半の日常（ビート2）**。ミナと少年が「好敵手」になる前に「最後の軽口」が来てしまい、頭で刺さるのに肚に落ちきらない。

方針：**「足す」より「既にある仕組みを見せる／揃える／削る」** ＋ **前半に緩みを少しだけ足す**。

## A. UI・ゲームデザイン提案（桜井）

各件「現象 → 原理 → お客様目線 → 具体案 → 狙う効果」。重要度順。

### 【高】① やさしさゲージ（Overload）がHUDに存在しない — 最大のリターンが見えていない
- **現象**: `GameManager.cs:351-399` にグレイズ(+0.035)・浄化(+0.12)で貯まり満タンで5秒「やさしさ全開（連射0.07s＋フォロワー全同期）」が発動する `Kindness` ゲージが実装済み。`Player.cs:253,284,354` が参照し手触りが激変。だが `Hud.cs` に描画が無く、`JustOverloaded`(GameManager:358) もUI未配線。
- **原理**: §2-3 リターンは即・明確に／§13 HUDは見なくても分かる／§2-4 攻めたほうが得。
- **お客様目線**: 「急に連射が速くなった」と気づいても**なぜ・どう貯めるか分からない**→能動的にグレイズを狙わず引き撃ち最適解に倒れる。ゲームの核（かすり）が死ぬ。
- **具体案**: 浄化カプセル(`DrawPurify` 244-257)直下かLIFE/BOMB近傍にバー新設（蓄積中=紫グラデ／全開中=金〜シアンで残時間減少）。Kindness≥0.85でふち明滅で「あと少し」予告。`JustOverloaded` 瞬間に中央トースト＋`FxLayer`発光（`DrawShotModeToast` 366-376を流用）。グレイズ時(`Player.OnGrazeAreaEntered` 423-431)にゲージがピクッと伸びる手応え。
- **狙う効果**: 最大のリスクリターンが可視化、初見から「弾に近づく動機」。引き撃ち最適解の解消。

### 【高】② ボム(X)・モード切替(V)・メニューのX(戻る)が衝突 — 誤爆の危険
- **現象**: プレイ中ボム=X(`Player.cs:289`)/切替=V(`Player.cs:265`)。メニューはX=戻る(Hub:220, Shop:100, DiffSelect:68)、HubではX=ショップへ。同じXが「貴重なボムを切る／戻る／ショップへ」と画面で意味が変わる。
- **原理**: §13 一貫性（同じ操作は同じボタン）。
- **お客様目線**: 戦闘中に思わずXで「なぜボムが減った!?」、ショップで「Xで強化画面? 戻るじゃ?」と混乱。最悪、戻すつもりでボム暴発。
- **具体案**: 破壊的操作(ボム)とキャンセル(X)を別キーに分離。ボム=Space/右Shift、切替=Tab等。Hub:222「X=ショップへダイブ」は別キー(例:S)へ寄せ、Xはどこでも「戻る/キャンセル」に統一。
- **狙う効果**: 誤爆ボム撲滅、画面間の操作一貫性。

### 【高】③ 会話開始で敵弾全消去＆操作ロック — テンポと緊張を切る谷
- **現象**: `Hud.cs:93-96` 会話中 `BubblePaused=true` で敵停止＋開始瞬間に `ClearEnemyBullets`。`Player.cs:225,278,290` で会話中は移動・射撃・ボム不可。`_messageTimer` は4.5〜6.0秒固定(`Hud.cs:124,133,148`)、スキップ手段なし。`CharsPerSec=48` の送り/早送り不可。
- **原理**: §3 テンポ／§8 ストレスとカタルシス／§13 メニューにもテンポを。
- **お客様目線**: 避けてる最中に止まり、弾も消え、6秒眺める。「早く次を」が切れる。
- **具体案**: **Zで早送り/スキップ**（1押しで全文即表示、もう1押しで次へ）。Hubの「Z すすむ」(`Hub.cs:142`)に**戦闘中HUDも揃える**。全消去(`ClearEnemyBullets`)は残すなら「花びらに変換」(ボムと同じ `BulletToPetal`)で消えた理由を画で返す。緊張を切りたくない短ナレは自機を止めず画面下に流す軽量表示も検討。
- **狙う効果**: 道中の緊張が会話で途切れない。読みたい人は読め、急ぐ人は飛ばせる。

### 【中】④ HUDの情報過多 — 周辺視を侵す
- **現象**: `DrawAll` が常時 LIFE/BOMB・浄化カプセル・SCORE・テレメトリチップ2種(`267-280`)・ショットモードチップ＋「V 切替」・ヒカゲスキル文言・下部ティッカー(`DrawTicker` 378-406 常時スクロール)を描画。さらにボスカード/スペルカード/トースト/会話が重なる。
- **原理**: §3 視認性／引き算 §13 情報を盛りすぎない §15 濃く。
- **具体案**(足すより削る): 戦闘中ティッカーをボス戦・高密度区間で自動的に薄く/停止（透明度を `StageProgress` や被弾危機で落とす）。テレメトリチップ(イ/コンボ)は変化時だけポップして数秒で薄れる方式に。「V 切替」ヒントは最初の数戦だけ。
- **狙う効果**: 弾の視認性が上がり、難易度が「読めなさ」でなく「避けられる難しさ」に寄る。

### 【中】⑤ ショップが情報過多／死蔵の強化8種 — とっつきの壁
- **現象**: `Shop.cs` 1画面に多数要素。`GameManager.Upgrades`(188-204) は14種定義だが、ショップに出るのはshot系3＋共通3=6種だけ。残り8種（機動力・回避域・ボム・最大♥・インプレ倍率・汚染耐性 等）は購入導線なし。過熱プレビュー(V, Shop:617-639)がデバッグ臭く一等地を占有。
- **原理**: §9 とっつき／§15 濃く・薄く広げない／§6 引き算。
- **具体案**: 「おすすめ」or 価格安い順ハイライトを1つ（初回は「光の出力」を光らせる）。死蔵8種を別タブ/スクロール枠で出すか設計から外す。過熱プレビューは設定/隠しに格下げし一等地を「次に買うと何が変わるか」に。バランス早見表はカード選択時に該当行をハイライト。
- **狙う効果**: 「稼ぐ→強くなる」の変換が一目で回り始める。

### 【中】⑥ 道中スポーンが難易度倍率を無視 — 緩急の段差
- **現象**: `Spawner.cs` は `MaxAlive=9`/`RampDur=60`/`IntervalStart=2.0→End=0.9` をハードコード。ボス弾は `BulletCountMul`(Easy0.38〜Lunatic1.9)等でスケールするのに、道中の敵数・湧き間隔は難易度非連動。
- **具体案**: `MaxAlive`/`IntervalEnd` を `BulletCountMul`/`DanmakuIntervalMul` で軽くスケール（例 `Round(9*clamp(BulletCountMul,0.5,1.5))`）。HP固定方針は不変。ランプを `StageTarget=24` の達成見込みと整合させボス直前で最大密度に。
- **狙う効果**: 選んだ難易度どおりの圧。道中(負荷)→浄化(解消)の波が一貫。

### 【中】⑦ ゲームオーバーの代償と復帰テンポ — 二重罰
- **現象**: 被弾で `TakeHit`(513)がフォロワー全離脱(530-535)＋残機-1。残機0で `GameOver`(544-557)→「くじけちゃった… Rでもう一度」を1.8秒固定で見せてから自動リロード。Rも待つ。
- **具体案**: ゲームオーバー演出中のRを即時受付（1.8秒待たず）。被弾時のフォロワー喪失を全損→1〜2体に緩める（少なくともEasy）。バナーはスキップ可。
- **狙う効果**: 「もう一回」が即出る。救出のごほうびが連続し再訪性が上がる。

### 【低】⑧ パネル（暴言吹き出し）の当たり判定が極小
- **現象**: `Panel.cs:42` 判定が半径3pxの円。見た目(`DisplayH=14`/グロー r≈3.2+Ink*0.8)より小さく「当たってる気がしない」。
- **具体案**: `Radius = 3f → 4.5f`。Ink残量で判定も少し可変。剥がし時に小ヒットストップ/閃光(`FxLayer`)を返す。
- **狙う効果**: 浄化の前進が手に伝わる。

### 【低】⑨ 難易度選択の賭け金可視化が弱い
- **現象**: `DiffSelect.cs` の弾密度ピップ(5段)は手書き `Tier.Density` で実 `BulletCountMul` と独立。
- **具体案**: ピップを `BulletCountMul` 由来で算出。選択中ティアに「弾×N.N／報酬×N.N」の1行サマリ。
- **狙う効果**: 難易度＝賭け金、が数字で腑に落ちる。

## B. シナリオ提案（麻枝）

### 全体診断
- **強み**: Acrostic仕込み(Prologue)→回収(Epilogue)の対構造（白眉）／善行の蓄積＝世界の秘密の反転（救った三人が全員少年の大切な人）／3ボスのアーキタイプ分け（レイ=承認/あかり=言えなかった想い/こはる=祈りの無力）。
- **最大の弱点**: beatsheetのビート2（日常）がほぼ無い。Prologueの毒舌初対面とFinal「最後の軽口」の間に、二人が笑い合う時間が一秒も無い。麻枝の公式「①好きにさせる→②意味を仕込む→③反転→④代償」の**①が薄い**。
- **第二の弱点**: 少年の「臆病さ」がFinalで初出（伏線になっていない＝P2の縁）。
- **第三の弱点**: ミナ自身の喪失（CARD4のミナ枠）が最後まで開示されず、代償の傷が浅い。

## C. 共通基盤：会話タグ・フォーマットの1本化（両者合意）

テンポ・間・弾消去・記憶フラッシュを**本文側から指定**できる土台。二人が最も時間をかけて握った設計。

### C-1. 形式：タプル拡張（インラインタグは不採用）
インラインタグ `[hold]` 等はタイプライター(`Hud.cs:84-85,434`)とのパースが地獄で表示事故の危険 → **タプル4要素化**に確定。
```
(int who, string text, string face, LineTag tag)

[Flags] enum LineTag {
  None=0, Fast=1, Slow=2, Hold=4, Purge=8, Flash=16, Bubble=32
}
```
- 既存配列は `tag` 省略オーバーロード(`None`扱い)で**無傷**。タグを足したい行だけ4要素目を書く。
- `Fast`=掛け合い高速送り／`Hold`=決定打の沈黙(Z無効の間)／`Purge`=その行頭で `ClearEnemyBullets`／`Flash`=`TriggerMemoryFlash` 発火／`Bubble`=全開ボイス別レイヤー。
- **付けすぎ厳禁**: 意味のある行だけ。デフォルト速度はUI側で持つ。

### C-2. Zの挙動を統一（一貫性 × 決定打のhold）
全行共通の2段Z：**Z=全文即表示 → Z=送り**。`Hold` 行だけ「1段目(全文)の後、指定拍は2段目を受け付けない＋▼非表示」を挟む。客は「Zで全文、Zで送り」だけ覚えればよい。
- 実装フック: `Step_Lines`(`StageRei.cs:105`)の `_lineHold>=0.25` を `Fast→0.12`、`Fast` 行は最短hold後に自動送り。
- Prologue `_line==6` の無音ハック(`Prologue.cs:115,251`)を汎用 `Hold` 挙動に昇格。

### C-3. テンポ シーン×速度 対応表（麻枝）
| シーン | 速度 |
|---|---|
| 各Stage Intro / 投稿・中継のノイズ / B-1軽量弾消去 | **fast** |
| ボス改心の入り（言い合い）/ Hub帰還会話 | **mid** |
| ボス改心の決定打 / B-2重厚弾消去 / Stage Clear着地 / Final・Epilogue | **slow + hold**（自動送りしない=Z待ち） |
- slow=自動送りしない。決定打を自動でめくらせない。行単位 `Hold` も可（BossIntro最後の1行だけ等）。

### C-4. 全開ボイス（やさしさ全開時の一言・麻枝）
発動は頻発するので決定打は温存。短く・所作寄り・連呼耐性優先で**2〜3本ローテ**、中央上/自機付近に0.8秒の小フキダシ別レイヤー（`_shotModeToast` 流用、戦闘を止めない）。
1. **「——とどく。」**（第一推奨。主モチーフ直結・最も連呼に強い）
2. 「いま、やさしくなれる。」
3. 「だいじょうぶ。聞こえてる。」

### C-5. 弾全消去の物語化（2段・麻枝）
会話開始の自動全消去(`Hud.cs:95`)を切り離し、`Purge` 行頭で明示発火。弾は「白い羽/光片になって落ちる」(浄化＝届いた の語彙)。
- **軽量版**(道中ナレ・速い・約1.5-2秒): `(3,"穢れが、波打って——")` ＋ `(1,"……しずかに。")` の2行目頭で消去。
- **重厚版**(ボス級・1ステージ1回・間を取る): `(2,"ぜんぶ、消えてしまえ！")`→`(1,"消さない。")`→`(1,"——ぜんぶ、わたしが受け取る。")`(この行で全消去＋一瞬白)→`(3,"弾が、ひとつ残らず、白い羽になって落ちた。")`。被弾救済に使う場合は無敵フレームを噛ませる。`bool _purgedOnce` で多重発火抑止。

### C-6. 記憶フラッシュの拡張（麻枝×桜井）
`TriggerMemoryFlash`(`StageImagery.cs:27`) を `Flash` タグ付きナレ行で発火。
- **Final**: 戦闘シーンなので同機構でいける。ただし `StageImagery` 側に「誕生フラッシュ」(Prologue `DrawIgnite` 211 の構図)の描画分岐を1個追加。
- **Epilogue**: `StageImagery` を持たない独立カットシーン → Epilogue自前で白フラッシュ1メソッド。発火は **Acrostic解錠の瞬間(`phase2→3`, `Epilogue.cs:109`)** に誕生の光を0.3秒。新しい絵は見せない（既視感が命）。

### C-7. PwChoices リジェクト文の選択肢別化（麻枝×桜井）
`_pwReject` 固定1個(`Epilogue.cs:110`) → `PwChoices` と同長の `PwRejects[]` を足し `_pwReject = PwRejects[_pwSel]`。間違うほど少年の輪郭が濃くなる＝不正解が報酬に。
- "0414"→「誕生日は、わたくしが勝手に決めた数字です。」／"MINA"→「それは、わたくしの名前。鍵じゃない。」／"天才"→「……それは、毎回言ってましたけど。違います。」

### C-8. 既読管理（周回テンポ・麻枝）
「情緒(泣かせ)=初回だけ／機能・状況=毎回」。粒度はシーン単位で十分。**自動カットでなくZで飛ばせる**を基本（初見保護）。
- 初回フル/2周目スキップ可: 各Stage Intro・Clear・ボス改心（2周目は短縮版を別途用意可）。
- 毎回(短く): BossIntro煽り・BurnDialog。初回のみ: Hub ReturnDialog。既読のみ静かに: ReplyDialog。
- 常に毎回フル(Z早送り許可): Final/Epilogue。

### C-9. LineKind 色設計（誰の声か・麻枝）
当事者(ミナ/少年/ボス)と環境ノイズ(投稿/中継/ナレ)を色と透明度で格付け分離。
- 投稿(4)=匿名群衆＝無彩色グレー＋テロップ枠（固有キャラ色を当てない）。中継(5)=「少年の声でミナが代弁」＝少年寄りだが彩度を落とす（現状 `中継=Info` で少年と同色は危険）。ナレ(3)=ト書き＝話者名なし・地色＋斜体/字下げ。
- 当事者会話は不透明帯で守り、環境ノイズは薄く（桜井④と直結）。**伏線は当事者会話側に寄せる**（薄い投稿に重要情報を仕込むと読まれない）。
- ボス(2)=穢れ色は改心の決定打で最後の1〜2行だけ浄化側(淡色)にトーン変化＝色で物語が動く。

## D. 二人の意見が割れた点 / トレードオフ（正直な記録）

1. **Acrostic二重化（食事の反復）の見せ方**: 麻枝「同色・同箱で気づかせる案も」⇔ **桜井は明確に反対**（色で手を引くのは野暮、2周目報酬として隠せ）。→ **隠す方を推奨**。
2. **戦闘中の掛け合い vs 敵全停止の間延び**: `BubblePaused`(`Hud.cs:96`)で会話中は敵完全停止。掛け合い5行を戦闘中に置くと弾幕が止まりSTGのテンポが死ぬ。→ **掛け合いは戦闘前stepに集約が必須条件**（Reiなら `case 1`, `StageRei.cs:77`）。
3. **弾消去の物語化 vs 手触り**: 演出を入れるほどボス戦のリズムが止まる。麻枝が「回数の決定権は桜井に譲る」と明言。B-2は1ステージ1回。
4. **Hold(沈黙)の多用 vs もたつき**: 「間」は希少資源。1シーン2〜3箇所が上限。泣かせ所が4箇所以上ならフラッシュ/弾消去で重みを付け分ける。
5. **既読スキップ vs 初見保護**: スキップを強くするほど初見が核心を誤って飛ばすリスク。「カットせずZで飛ばせる」は安全側だが周回テンポを完全には救わない。
6. **色の格付け vs 仕込みの自由度**: 環境ノイズを薄くすると、そこに伏線を仕込めなくなる。伏線は当事者会話側に寄せる、で合意。
