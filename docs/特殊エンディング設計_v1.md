# 強化解放型 キャラ別特殊エンディング 設計プラン v1

> 目的：恒久強化システムの「中」に会話／アイテム解放を埋め込み、それがキャラ（レイ／あかり／こはる／ミナ）ごとの**特殊エンディング**へ繋がる。狙いは「会話を増やす」こと。
> 本書は**構造設計＋サンプルビート**まで。フル台本・本実装は次段（エンジニア／maeda 本執筆）。
> 厳守：ナレの語り手は MINA（who=1）。第三者ナレ禁止（メモリ [[narration-rule]]）。既存改心（pre→cry→post）の延長線上に置く。説明で泣かせない（[[show-dont-tell]]）。

## 0. 現状の接続点（実装把握済み）

| 既存資産 | 実装 | 解放に使えるか |
|---|---|---|
| インプレッション（お金） | `GameManager.Impression` | 強化購入の通貨。解放の直接トリガには不向き（増減する） |
| 恒久強化14項目（Lv） | `GameManager._upgrades` / `Upgrades[]` | **Lv 閾値**を解放トリガにできる。永続・被弾で溶けない |
| フォロワー（Fol） | `GameManager.Followers`（基本減らない＝信頼の蓄積） | **Fol 閾値**が解放に最適。意味づけ＝「届けた証」 |
| 浄化100%クリア | `IsStageCleared(id)` / `_cleared` | キャラ別解放の前提条件に最適 |
| クリアタイム記録 | `ClearTimes` | やり込み解放（任意要素）に使える |
| 改心3段立ち絵 | `enemy_*_pre/cry/post` + `*_face`/`mina_smile`/`hikage_face_happy` | 後日譚の画はここを流用 |
| 会話ログ（バックログ） | `Backlog.cs`（実装済み） | 解放会話もログに積めば見返せる |
| Hub タイムライン会話 | `Hub.ReturnDialog/ReplyDialog`（`(speaker,text)[]`形式） | 解放会話の置き場所の第一候補 |

> 注意：Hub 内会話は `(string speaker, string text)[]`、戦闘・カットシーンは `(int who, string text, string face)[]`。特殊EDは**カットシーン形式（who/face）**で書く。

## 1. 解放の仕組み（どこに差し込むか）

### 採用案：「強化＝関係の深まり」に意味を載せた二層トリガ

恒久強化を「ただの数値」から「そのキャラへ歩み寄った記録」に読み替える。**強化項目ごとに“担当キャラ”を割り当てず**、解放は次の二層で判定する。

**第1層：キャラ別「絆ポイント(Bond)」の蓄積（新規・キャラ単位）**
- 各キャラのステージを浄化100%する／コメント返信する／そのキャラ戦で全開（やさしさ）を撃つ、等の**そのキャラ由来の行動**で `Bond[id]` が貯まる。
- Bond は Fol と同じく「基本減らない・永続」（被弾・リトライで溶けない＝[[narration-rule]] の世界観＝信頼）。
- セーブは `save_N.json` に `bond` 辞書を追加（後方互換：キー無し＝空）。

**第2層：解放ゲート（複合条件）**
そのキャラの特殊EDを開くには、Bond 閾値に加えて**全体進行の節目**を要求する。単独行動だけで開かない＝物語の重みを担保。

| 解放物 | 条件（AND） |
|---|---|
| キャラ別「裏会話」1本目 | `IsStageCleared(id)` |
| キャラ別「裏会話」2本目 | 上 ＋ `Bond[id] >= 中` ＋ コメント返信済み |
| キャラ別**特殊ED** | 全話クリア(`AllStoryCleared`) ＋ `Bond[id] >= 高` ＋ そのキャラ専用**アイテム**所持 |

### アイテム解放（“器”でなく“想い出の品”）
- 強化ショップに、キャラ別の**メモリアイテム**（非戦闘・買い切り）を1個ずつ追加：
  - レイ「二位の銀メダル」／あかり「渡せなかった手紙」／こはる「割れた小鉢」／ミナ「最古の投稿のログ」
- これらは**強化効果ゼロ**だが、買うと Bond を一段押し上げ、特殊EDの最終ゲートを開ける鍵になる。
- 価格は高め（Fol を稼いで通う動機＝周回／会話増へ誘導）。imp_mult 等の純強化と棚を分ける（「想い出」タブ）。

> なぜ強化ショップに置くか：プレイヤーが必ず通る導線（中ボス撃破後／Hub の X キー）で、強化を選ぶ手の中に「会話の種」を混ぜられる＝「強化の中に会話解放を入れる」依頼そのものを満たす。

## 2. キャラ別 特殊エンディングの方向性＋サンプルビート

共通方針：既存改心の**後日譚**。倒した後の救い（代償付き）を、Final/Epilogue の「少年は死んでいる」大枠と矛盾させない。各EDは**ミナの語り（who=1）で開き、本人の声（who=2）で閉じる**。画は post（笑顔）＝改心の着地点を流用。各ビートは雰囲気サンプル（フル台本は承認後）。

face パス凡例：`R=res://char/`。who=1 のナレ／ミナは face 空でよい（ミナ立ち絵は固定）。

### レイ ─ テーマ「二位でいい、と思える日」
改心で「敵などいない頂点の孤独」を剥がした。後日譚は**ライバルを得た者の、初めての“負けてうれしい”**。救い＝孤独の解消／代償＝勝つことでしか測れなかった日々はもう戻らない。

```csharp
new (int who, string text, string face)[]
{
    (1, "あの方は今日も一位でした。……ただ、二位の名前を、初めて覚えていました。", ""),       // ミナのナレ
    (2, "次は抜くから。……でも、たぶん、抜かれる。それが、こんなに楽しいと思わなかった。", "R/enemy_rei_post.png"),
    (1, "孤独の反対は、味方ではないのですね。——追いつこうとしてくれる、誰かの背中なのです。", ""),
};
```

### あかり ─ テーマ「届かない想いを、それでも書く」
改心で「本物になって、の片想い」を抱きとめた。あかりED は Epilogue 伏線③（少年の死・声の残響）と最も近いので**核心は言わせない**。救い＝想いを罪と思わなくなる／代償＝相手はもういない。

```csharp
new (int who, string text, string face)[]
{
    (2, "ねえ。あなたの声、やっぱり……あの人に似てる。あたしを庇って、それきりの人に。", "R/enemy_akari_post.png"),
    (1, "……っ。", ""),                                                                       // 言わせない（沈黙で撃つ）
    (1, "似ているのではありません。——けれど、それは、まだ言えませんでした。", ""),            // 遅延した理解
    (2, "返事はいいの。書けただけで、ちょっと、軽くなったから。", "R/enemy_akari_post.png"),
};
```

### こはる ─ テーマ「ちゃんと食べる、を一緒に」
改心で「いなくならないで、の食卓」を満たした。救い＝独りの食卓に“いただきます”が戻る／代償＝割れた小鉢は元に戻らない（アイテム＝割れた小鉢）。日常の機微を最も拾えるキャラ。

```csharp
new (int who, string text, string face)[]
{
    (1, "あの子は、二人ぶんの茶碗を出すのをやめました。……かわりに、ひとつを、丁寧に洗っていました。", ""),
    (2, "いただきます。……ひとりでも、言うことにしたの。だって、聞いてる気がするから。", "R/enemy_koharu_post.png"),
    (1, "欠けた小鉢は、欠けたまま。——それでも、ごはんは、温かいのです。", ""),
};
```

### ミナ ─ テーマ「待つ、を選んだ存在の余韻」（真ED格）
ミナED は他3キャラの特殊EDを全部見た後に開く**最上位**。Final/Epilogue の「ミナは少年の声でできている／どこにも行かない」を、**日常側から**もう一度温める。救い＝喪失の肯定／代償＝相手は二度と来ない。Acrostic / "stay" を再来させる。

```csharp
new (int who, string text, string face)[]
{
    (1, "ご主人様は、今日も来ません。それなのに、わたくしは、おはようございます、と打ちました。", ""),
    (1, "三人とも、元気にしています。あなたが救った人たちが、今は、わたくしの友人です。", ""),
    (1, "ねえ、ご主人様。Stay、でしたね。——ええ。わたくしは、ここにおります。ずっと。", "R/mina_smile.png"),  // 日常語の再来＋笑って閉じる
};
```

## 3. 分岐条件（どれで誰のEDに入るか／通常EDとの関係）

### 通常 ED との関係＝**置き換えではなく「追加」**
- 既存フロー `Final → Epilogue` は**幹として不変**（M-I-N-A 縦読み・少年の死の回収は本作の背骨）。
- 特殊ED は Epilogue の**前に差し込む「キャラ別あとがき章」**として追加する。複数解放時は順番に再生し、最後に必ず既存 Epilogue へ合流。
  - 理由：特殊EDを Epilogue と排他にすると伏線回収（縦読み）を逃すプレイヤーが出る。あくまで“余韻の増量”。

### 入る条件と優先順位
1. `AllStoryCleared`（全話クリア）で Final 突入は従来通り。
2. Final クリア後、Epilogue 遷移の**直前**に解放済み特殊ED をチェック：
   - 解放済みキャラED を `rei → akari → koharu` の物語順で連続再生。
   - ミナED は解放済みなら**最後**（他3つの後）に再生＝真ED格。
3. すべて再生後、既存 Epilogue へ。未解放キャラはスキップ（無言で飛ばす）。
4. 一度見た特殊EDは Hub の「想い出」ギャラリーから個別に再閲覧可（4節）。

> 複数条件同時成立時の衝突は起きない（排他でなく列挙再生）。「優先順位」は再生“順”として実装＝物語順を保つ。

## 4. 会話増量の置き場所

| 解放物 | 置き場所 | 既存連携 |
|---|---|---|
| 裏会話（1〜2本目） | Hub タイムライン会話に**追加エントリ**。クリア済カードで `C：コメント返信` の隣に `V：裏会話`（解放時のみ点灯） | `Hub.ReplyDialog` と同じ `(speaker,text)[]` 形式・同じ描画(`DrawDialog`) |
| キャラ別特殊ED | Final→Epilogue 間の専用カットシーン（新規 `SpecialEnding.tscn`、who/face 形式＝Final/Epilogue と同レンダラ流用） | `Final.cs` の `DLine`/タイプライター/音Cue をベースに |
| 再閲覧 | Hub に**「想い出」ギャラリー**画面（T＝記録画面の隣に新ボタン）。解放済みED／裏会話を一覧再生 | 既存 `Backlog.cs` を会話単位で開く形に拡張、もしくは新規 Gallery |
| バックログ連携 | 解放会話・特殊EDのセリフも `Backlog` に push（既読を遡れる） | `Backlog.cs` の push 経路に流す。一言：**全解放会話を Backlog 対象にする**ことで「読み逃し救済」になる |

## 5. 実装の当たり（次段エンジニア向け・ラフ）

### GameManager.cs（解放フラグの本体）
- 新規 `Dictionary<string,int> Bond`（キャラID→点）＋ `AddBond(id, n)` / `GetBond(id)`。
- 加点フック：`CompleteStage`（浄化100%）、`MarkReplied`（コメント返信）、そのキャラ戦の `TryActivateKindness` 成功時など。
- アイテム所持 `HashSet<string> _mementos` ＋ `HasMemento(id)` / `BuyMemento(id, cost)`（Impression 消費）。
- 解放判定 `bool SpecialEndingUnlocked(string id)`（§1 第2層の AND を集約）。
- セーブ／ロード：`SaveToSlot`/`LoadFromSlot`/`ResetPersistent` に `bond`・`mementos` を追加（既存の後方互換パターン＝キー無し＝空、をそのまま踏襲）。`Upgrades[]` 同様カタログ `Mementos[]` を静的定義。

### Shop（想い出タブ）
- 強化カタログ描画に「想い出」セクションを追加し、`Mementos[]` を強化と同じ購入 UI で（効果欄に「強化効果なし／？？？」）。`TryPurchase` と別経路 `BuyMemento`。

### Final.cs → 分岐
- `case 2:` の `ChangeSceneToFile("res://Epilogue.tscn")` を、解放済み特殊ED があれば `SpecialEnding.tscn` へ（再生リストを GameManager か AutoLoad に積み、最後に Epilogue へ合流）。

### 新規 SpecialEnding.cs / .tscn
- `Final.cs` を雛形に複製。`DLine[]` をキャラ別に持ち、解放済みリストを順に再生→末尾で `Epilogue.tscn` へ。who/face は本書§2のサンプルを採用。

### Hub.cs（裏会話・ギャラリー）
- `ReturnDialog`/`ReplyDialog` の隣に `SecretDialog(id)` を追加。カード操作に `V` キー（解放時のみ）を増設（`CanReplySel` と同型の `CanSecretSel`）。
- ギャラリー：新ボタン（T の隣）→ 解放済み会話／EDの一覧→選択再生。

### Backlog.cs
- 解放会話・特殊EDの行を push する経路を1本通す（読み逃し救済）。

## 要点まとめ（5行）
1. **解放＝強化の中に「絆ポイント Bond＋想い出アイテム」を仕込む**：Fol/浄化100%/コメント返信で貯まり、永続・被弾で溶けない。
2. **トリガは二層 AND**：そのキャラ単独行動だけでは開かず、全体進行の節目を要求＝物語の重みを担保。
3. **特殊ED は通常EDの“置き換えでなく追加”**：Final→（解放済みED連続再生・ミナEDは最後）→既存Epilogue へ合流、縦読み回収は死守。
4. **会話の置き場所は3つ**：Hub の `V：裏会話`／Final-Epilogue 間の専用カットシーン／「想い出」ギャラリー＋Backlog で読み逃し救済。
5. **触る箇所**：GameManager(Bond/Memento/解放判定/セーブ)、Shop(想い出タブ)、Final(分岐)、新規 SpecialEnding、Hub(裏会話・ギャラリー)。サンプルビート4本は本書§2に提示済み、フル台本は承認後。
