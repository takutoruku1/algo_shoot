# オープニング・エンディングと戦闘／メニューの見た目の統一（2026-09-07 査定）

ユーザー指摘: 「オープニング・エンディングの背景や演出、セリフの枠と、シューティングゲームとかメニューとかの雰囲気が違いすぎるから、シューティングゲームやメニューの見た目に合わせて作り直してほしい」。

## 1. 浮いている原因（実装値つき）

### A. 座標系 ← 本丸。他の8割はこの副作用
- `Prologue` / `Final` / `Epilogue` が 384×216 の**生座標**。`Credits` は既に設計座標（1280）なので、**浮いているのはこの3画面だけ**。
- 本文サイズ `CutBody = 8` に対し戦闘は `FontBody = 17`。実画面で約2倍の差。定義のコメント自身が「384系では8が可読下限」と認めている＝**可読下限で運用している画面がある**。
- 話者名 7 対 19、送りヒント 6 対 13。**`FontSmall` は「実効3.3pxで可読下限割れ」として引き上げ、`FontTiny(9)` は廃止したのに、メニューで禁止した大きさをカットシーンだけが使い続けている**。
- リトライチップのときだけ設計座標に切り替わるので、1画面に2つの座標系が同居し、チップだけ正しい大きさで出て本文の小ささが際立つ。

### B. セリフの枠
- **塗り色と高さ比は既に一致**（角丸・背景色・ボーダーは換算上正しい）。
- **行間が違う**。戦闘は 1.55 倍、カットシーンは 1.0。2行のセリフが窮屈。
- **立ち絵の居場所が違う**。戦闘は箱の中・左で呼吸とうなずきと表情クロスフェードつき。プロローグは箱の外・画面中央で**呼吸もクロスフェードも無し**。同じミナが戦闘では箱の中で呼吸し、プロローグでは棒立ち。
- 戦闘は「あなた」に下書きの印を出すが、**プロローグは立ち絵も印も無い**。全編が下書き選択の話なのに、その記号を使っていない。
- ナレの作法が2種類（戦闘は専用の中央テロップ箱、Final はセリフの箱を色違いで代用）。

### C. 文字
- 先日導入した `TextStyle` を、**この3画面だけ1箇所も使っていない**。全部が生の描画と裸の数値。字間も行間もかからない。
- 定義側のコメントが「カットシーンは別スケールなのでこの定数は使わない」と**現状を追認する形で書かれており**、次の担当がまた分岐させる温床になっている。

### D. 背景
- **プロローグ**は全編ほぼ単色黒。層背景もビネットもグレードも無し。自前レイヤーの強度はメニューとほぼ同じだが、**主体の色がコード緑**。メニューと戦闘は藍〜紫。**プロローグだけ緑の世界**＝色的な正体。
- **Final** はほぼ純黒1色。**ゲーム最大の山場が全画面で一番情報量が少ない**。
- **エピローグ**は7層を実装済みで、**背景だけは既に戦闘水準**。問題は前景のみ。
- メニュー系の共通レシピは3行（縦グラデ → 上端中央の放射グロウ → 走査線）。**カットシーン3画面はこの3行を1つも呼んでいない**。

### E. 色 ← 情緒的に一番効いている不統一
- **同じミナの話者色が、戦闘では紫、カットシーンではシアン**。視覚的に別人。
- 「あなた」もシアンと暖色に割れている。
- 本文色もほぼ同じだが微妙に別。

### F. 演出の語彙
| 語彙 | 戦闘・メニュー | カットシーン |
|---|---|---|
| 角丸パネル | あり | あり（合っている） |
| 縁光・放射グロウ | あり | **無し** |
| 脈動 | Sin 補間 | **無し**。点滅は矩形波2値でカクつく |
| squash→pop | あり | **無し** |
| ぴこんと出るカード | あり | **P4 だけあり**＝プロローグ内でも P4 のカードだけ本編と同じ手触りで前後から浮く |
| 立ち絵の生命感 | 呼吸・うなずき・クロスフェード | **無し** |
| ビネット | あり | **無し** |

## 2. 統一の方針（戦闘・メニュー側へ寄せる）

**捨てる**: 生座標／独自のサイズ体系／生の描画と裸の数値／カットシーン専用の話者色／矩形波の点滅／Final の純黒背景。

**借りる**: 戦闘の会話バーのジオメトリ丸ごと、立ち絵の作法、下書きの印、送りチップ、話者色の定義、メニューの背景3行、エピローグの層の手口、`TextStyle`、通知カードの手触り。

**理想**: 起動からエンディングまで通して、**セリフの箱の位置・大きさ・立ち絵の居場所・ミナの色が一度も変わらない**。変わるのは背景と表情だけ。今は箱が2回作り替わって見える。

## 3. 修正の順序と規模

| 順 | 項目 | 規模 |
|---|---|---|
| P1 | 3画面を設計座標へ | **L** |
| P2 | `TextStyle` へ寄せる（行間 1.55 が一番効く） | **M** |
| P3 | 話者色を戦闘側の定義に一本化 | **S** |
| P4 | 背景の下地3行をプロローグと Final へ | **S** |
| P5 | 立ち絵を箱の中へ＋呼吸＋下書きの印 | **M** |
| P6 | 2値点滅を Sin 補間へ（戦闘側にも同じ2値があるので両方直す） | **S** |
| P7 | エピローグの層スケール確認 | **S** |

**P1 で一番事故る箇所**: エピローグの層のスケール定数が画面高から算出されているため、設計座標にすると**層が4倍で描かれる**。固定値に直すこと。

**P1 の換算**は戦闘の会話バーの値に直接合わせる。折り返し幅は戦闘側の関数を公開して共有し、式の二重定義を作らない。

## 4. カットシーン固有として残すもの（台本を読んだ上での判定）

1. **起動ログの素っ気ない端末画面は意図的。対象外**。台本にログが行単位で正典として書かれ、明滅の演出指定まである。書体と色は役割色であって不統一ではない。**ただしサイズだけは上げる**。特に「過去に触れる唯一の行」と位置づけられた行を可読下限で出しているのは演出意図に反する。
2. **Final の白フェードは残す**。背景ではなくトランジション。
3. **ナレの中央寄せ・全文フェードインは残す**。ただし箱は戦闘のナレ専用箱へ。
4. **P4 の通知カードは残す。むしろ広げる**。本編と同じ部品を使う唯一のカットシーン演出で、統一の見本。
5. **スタッフロールの行間**はやや広いので、本文の行高に合わせて詰める。移行時に目視調整が要る唯一の箇所。

## 5. 背景の新規生成 → 当面不要

- **エピローグ**: 7層あり。生成不要。
- **プロローグ**: 生成不要。**「起動直後の何もない空間」であること自体が台本の設定**なので、絵を置くと台本と衝突する。下地の色を緑から藍に変えるだけで空気が揃う。
- **Final**: 第1弾では不要。下地の放射グロウの色を穢れの色に差し替えれば、汚染された最終決戦の空気になり、かつメニューと同じ語彙になる。P1〜P6 後に見て、それでも貧しく見えたら初めて発注する。

## 6. 指揮官の決定

1. **ミナの話者色は戦闘の紫に統一**。紫は HUD・ハブ・ボスバーで既に「ミナの色」として広く使われているため。
2. **`END` / `【終】` は最大サイズ**（一生に一度しか出ない行）。
3. **起動ログは書体・色・素っ気なさを残し、サイズだけメニュー基準へ上げる**。
4. **立ち絵は箱の中へ移す**（戦闘と揃える）。
5. Final の背景発注は P1〜P6 後のスクショを見てから判断。

## 7. 着手の注意

`Prologue.cs` と `Hud.cs` を別担当が編集中。P1・P5・P6 は両ファイルに触るので競合確認が必須。P2・P3・P4・P7 は先に進められる。ただし P1 を後回しにすると P2 の換算が二度手間になるので、競合が短期で解けるなら P1 優先。
