# ボスの第二形態 — 設計（2026-09-07）

> ユーザー決定（2026-09-07）「ボスの第二形態、見た目と BOSS の周囲を回っているアイテムを派手にする」に対する設計。
> 一律テーマ（`docs/20260907/テーマと構想_2026-09-07.md`）＝**下書き＝本音／投稿＝仮初の自分**を、形態変化そのものに乗せる。

## 1. 意味づけ — 一形態＝仮初／第二形態＝本音

第二形態は「壊れて中身が出る」のではない。**繕っていたものが剥がれて、隠していた本音が溢れている**姿。
レイは既に「ガワが割れて中の人」でこの型なので、あかりとこはるにも同じ筋を通す。

| | 一形態＝仮初の自分（投稿） | 第二形態＝本音が露出した姿（下書き） |
|---|---|---|
| **あかり** | 膝を抱えてスマホを見ている。既読を待つ静かな姿＝「大丈夫」の顔で世間に見せている姿 | 待つのをやめて顔を上げ、**取り消した一通が体の外へ溢れている**。「返して」が隠せなくなった姿 |
| **こはる** | 明るい子の顔のまま、ペンライトを立てて視線に囲まれている＝学校で通している姿 | 明るさが剥がれ、**送れなかったコメントが束になって身体に貼りついている**。「送れない」手が止まったまま露出した姿 |
| **レイ** | 豪華なガワの笑顔。伸びていた頃のまま配信している姿 | **ガワにひびが入り、割れ目から中の人の光が漏れている**。笑顔は保ったまま、中に誰かいるのが見えてしまう姿 |

- レイだけは既存の改心演出（`ShellPeelFx` によるガワ割れ＝決定打で中の人が出る）と喧嘩させない。
  第二形態では**割らない・中の人を出さない**。ひびと漏れる光だけに留め、「割れる」は決定打に取っておく。
  ＝第二形態はガワ割れの**予告**になり、三面目の構図（作ったものが作った人より大きい）が段階的に立つ。

## 2. 切り替えのタイミング — 既存の閾値に乗せる

新しい仕組みは足さない。各ボスが既に持つ `PatternThresholds` の **index 1（中盤）** に乗せる。

| ボス | PatternThresholds | 第二形態の発火 | 同じ節目の既存ギミック |
|---|---|---|---|
| あかり | `{ 0.78, 0.52, 0.26 }`（`src/BossAkari.cs:23`） | **0.52** | イライラ棒「雨の帰り道」（`corridor_hp` 0.52）＝同フレーム |
| こはる | `{ 0.78, 0.50, 0.26 }`（`src/BossKoharu.cs:95`） | **0.50** | 食事（`meal_hp` 0.52）の直後 |
| レイ | `{ 0.78, 0.50, 0.26 }`（`src/BossRei.cs:42`） | **0.50** | なし（`relay_hp` 0.26 は最終閾値側） |

**なぜ index 1（中盤）か**
- index 0（0.78）は早すぎる。開幕直後に本音が出ると「仮初で戦っている」時間が成立しない。
- index 2（0.26）は遅すぎる上、三人とも終盤の一発ギミック（雨の帰り道／十字火／最終選考）とフィナーレ宣言が
  密集する節目で、そこへ形態変化を重ねると宣言カードが潰し合う（`BossKoharu.cs:539` の `holds` の注記と同じ事故）。
- index 1 なら HP の折り返しで、**残り半分は本音の姿で戦う**＝配分として読みやすい。

**実装の乗せ方**: `Enemy` に `Form2TexPath`（第二形態の待機絵）を足し、`AdvanceForm2()`（一度だけ）を用意する。
各ボスの `OnHpChanged` にある `_beatsFired` を進める既存ブロックで、`_beatsFired == 1` へ進んだ瞬間に呼ぶ。
`Form2TexPath` が空なら何も起きない＝他のボス（ヒカゲ・ミナ・カメオ）は完全に不変。

**一拍**: 既存の `OnBarBroken` と同じ語彙を流用する。`SwapBody`（クロスフェード＋squash→pop、`src/Enemy.cs:894`）で
待機絵を差し替え、`Hud.Flash()` ＋ `Audio.PlaySpell()` ＋ 軽い `GameCamera.Shake`。**新しい演出機構は作らない**。
弾は止めない（ヒットストップは入れない）＝弾幕の読みを切らない。

## 3. 見た目の差分 — 待機の 1 枚だけ

`char/v3/boss_<name>_body_idle2.png`（透過・高さ 720・エフェクトなし・単色キー抜き）を三人分、**待機のみ**。

**攻撃・被弾の絵は作らない**（3 倍になる）。既存の `boss_<name>_body_{attack,hit}.png` をそのまま流用する。
理由と成立の根拠:
- 攻撃絵は `AttackPoseDur` の**一拍だけ**表示して待機へ戻る（`src/Enemy.cs:454-474`）。形態の印象を決めるのは
  画面に出ている時間の長い待機絵であって、瞬間の攻撃絵ではない。
- 姿勢オフセット表（`BossParts.BodyOffsets`）は姿勢ごとなので、**idle2 は idle と同じ足元中央・同じ画像幅**で
  発注すれば表を触らずに済む＝攻撃絵との往復で体が滑らない。これを発注条件にする。
- 色調でのごまかし（`Modulate` を紫に寄せる等）は**やらない**。アニメ塗り 2 段の色設計を後段で潰すため（13 の方針）。
  差は描き分けで出す。

## 4. 部品を派手にする — 何を、どれだけ

`BossParts` に `EnterForm2()` を足し、既存の部品表（`PartsOf`）の値に**倍率を掛ける**だけにする。
新規の部品画像は**足さない**（既存の 30 点で足りる。増やすと生成量が三倍側へ戻る）。
やり方は人物ごとに一つに絞る（全部盛りにしない＝弾が読めなくなる）。

| ボス | 派手にするやり方 | 具体 |
|---|---|---|
| **あかり** | **二重の輪にする**（＝取り消した一通が一周では収まらない） | 既存のカード 3 枚（半径 0.60・ω0.63）に、**外側の輪をもう 1 周**（半径 0.86・逆回り ω −0.50・サイズ 0.85 倍・α0.70）で 3 枚複製。合計 6 枚。回転速度は **1.35 倍** |
| **こはる** | **数を増やす**（＝送れなかったコメントが束になる） | 視線の線 4 本 → 位相をずらして **8 本**（追加 4 本は半径 0.20〜0.26 の外周・α0.45）。菫の粒 3 → **6**。回転速度 **1.4 倍**、脈動 **1.6 倍** |
| **レイ** | **大きくする＋速く回す**（＝ガワが膨れて手に負えない） | 飾り枠 7 点を **1.18 倍**、空の吹き出し 4 枚を **1.25 倍**・半径 **1.12 倍**・ω **1.5 倍**、星 3 → **6**。ひび（`crack`）を**常設の薄い層**として本体に重ねる（α0.22・脈動あり） |

**弾の視認性を守るための上限**（設計時に決めて、実機で越えていたら戻す）
- 追加する部品の α は既存より必ず低く（0.45〜0.70）。**加算合成（Add 層）の部品は増やさない**（あかりの `phone_screen`、
  こはるの `gaze_ray`、レイの `ray_*` は本数・α とも据え置き）。光り物を増やすのが一番弾を潰す。
- 公転半径の上限は本体高の **0.90 倍**まで（＝あかりの外周 0.86 が最大）。それ以上は弾の湧く帯へはみ出す。
- Z は既存のまま（Back −3／Front −1／Add −1）。弾（Z 0）と自機（Z 10）は必ず部品より前。この規則は動かさない。

## 5. 触らないもの

- 一形態の見え方（`PartsOf` の既定値、`boss_*_body_idle.png`）は**一切変えない**。
- 当たり判定（`body_radius`、`_bodyShape`、`GlobalPosition`）、弾幕の値（`config/boss_stats.ini`）、
  HP・バー本数、既存の一発ギミック（雨の帰り道／食事／十字火／最終選考）、改心の三段（pre→cry→post）、
  レイのガワ割れ（`ShellPeelFx`）。**第二形態は見た目だけ**で、難易度は動かさない。

## 実装の記録（2026-09-07 実装後に追記）

設計から変えた点だけを書く。理由はすべて「実機で撮って確認した結果」。

### 配線した場所

| 何を | どこ |
|---|---|
| 第二形態の待機絵の口 | `src/Enemy.cs` `Form2TexPath`（未設定のボスは完全に不変） |
| 移行の本体 | `src/Enemy.cs` `AdvanceForm2()` |
| 部品を派手にする | `src/fx/BossParts.cs` `EnterForm2()` |
| 姿勢オフセット | `src/fx/BossParts.cs` `BodyOffsets` の第4列（`Pose.Form2`。Pose は末尾に追加＝既存の添字は不変） |
| 発火 | 各ボスの `OnHpChanged` の既存の閾値ブロックで `if (_beatsFired == 2) AdvanceForm2();` |

`AdvanceForm2()` は `PreTexPath` 自体を差し替える。これで攻撃の一拍から戻る先（`TickAttackPose`）も
自動的に第二形態になり、他に手を入れる場所が無くなる。

### 姿勢オフセットの実測値（720px 基準・足元中央）

| | idle | idle2 | Form2 オフセット |
|---|---|---|---|
| あかり | (294, 719) / 幅487 | (205, 718) / 幅455 | (73, 0) |
| こはる | (427, 629) / 幅626 | (410, 681) / 幅639 | (23.5, −52) |
| レイ | (255, 719) / 幅533 | (230, 715) / 幅516 | (16.5, 4) |

### 設計から変えた 2 点（どちらもレイ）

1. **枠の拡大を 1.18 倍 → 1.10 倍に下げ、脈動を 1.3 → 1.5 倍に上げた**。
   1.18 倍は実機で枠が外へ張り出して弾の通り道へ寄った。「膨らんだ」は張り出しではなく脈動で出す。
2. **ひびの重ね方を変えた**（Front・α0.22・白 → **Add・α0.42・金の掛け色**・脈動 0.16）。
   本体絵 `boss_rei_body_idle2.png` にひびは描いてあるが、表示高 56px まで落ちると金の縁取りと
   見分けが付かず「割れている」が読めなかった。素材 `crack.png` は菫の細線なので、菫のガワに
   そのまま重ねても沈む。加算合成＋金の掛け色にして初めて「中から光が漏れている」に見えた。
   これに合わせて `BossParts.Part` に `Tint`（既定は白）を足した＝既存の部品の見え方は不変。

### 検証の結果

- `Akari.tscn` / `Koharu.tscn` / `Rei.tscn` を `--boss --qa --assist --easy` で三面とも **clean run**。
- 所要時間は変更前後で有意差なし（変更前 170.5 / 164.5 / 163.3s、変更後 171.5 / —（次面へ進行） / 155.4s。
  差はオートパイロットのばらつきの範囲で、ゲーム側の数値は一つも動かしていない）。
- `dotnet build` 0 warning / 0 error。
- 弾の視認性: 三面とも撮った画像で確認し、弾が部品に埋もれる箇所は無かった。
  あかりは二重の輪の中でも青い弾・赤い菱形がはっきり分離して読める。
