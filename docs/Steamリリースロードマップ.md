## Phase 2 — 製品品質（Steam標準への引き上げ）【Phase 1と一部並行可】

- [ ] **キーリバインド実装**: `src/Settings.cs` のKeyBindを表示のみ→実動に。STGでは強く期待される機能。パッドのボタン再割当も。
- [ ] **SE実音源化（任意だが推奨）**: 手続き合成SEのうち、被弾・浄化・ボム撃破など感情の山場だけでも実音源/リッチ化。全差し替えは不要。
- [ ] **解像度セレクタの実動化 or 撤去**: 表示のみのUI（解像度/FPS）は機能させるか消す。動かない設定項目はレビューで叩かれる。
- [ ] **ローカライズ方針決定**: 
  - 案A: 日本語のみで出す（ストアページに明記）→ 追加作業ゼロ、ただし市場は大きく狭まる
  - 案B: 英語対応 → 全テキストがC#ハードコードなので、`tr()` 化 or 辞書テーブル抽出のリファクタが必要。**やるなら早期に決める**（後からの抽出コストが増え続ける）
- [ ] **実績の設計**: クリアタイム記録(`ClearTimes`)を土台に、実績リスト（全ステージクリア、ノーダメ、各難易度、隠し=合言葉"stay"系など15〜25個目安）を紙で設計。実装はPhase 3。

## Phase 4 — ストアページ & マーケティング【リリースの最低1ヶ月前には開始】

Steamの制約: **「Coming Soon」ページはリリースの最低2週間前に公開必須**。ページ審査に2〜5営業日、ビルド審査にも1〜3営業日かかる。ウィッシュリスト獲得のため、実際は**1〜3ヶ月前公開が定石**。

- [ ] **ストアアセット制作**（artist ワーカー＋gen-asset。AI生成の場合ストア申告に含める）:
  - カプセル画像一式（メイン 616×353、小 231×87、ヘッダー 460×215、縦 374×448、ライブラリ 600×900 / 920×430 ほか）
  - スクリーンショット5枚以上（1920×1080、実ゲーム画面。screenshots skillで取得→アップスケール検討）
  - **トレーラー**（demo-video skill が土台に使える。30〜60秒、最初の5秒に見せ場）
- [ ] **ストア文面**: 短文説明・詳細説明・タグ（Shoot 'Em Up / Bullet Hell / Story Rich / Anime）・対応言語・システム要件。日本語＋（案Bなら）英語。
- [ ] **AI生成コンテンツ開示文**の記入（提出フォーム必須項目）。
- [ ] **年齢レーティングアンケート**回答。
- [ ] **価格決定**: コンテンツ量（3ステージ＋α、周回前提）から $5.99〜9.99 帯が相場感。地域価格はSteam推奨値ベース。
- [ ] **（任意）体験版 or Next Fest参加**: Stage0＋Stage1を切り出したデモはウィッシュリストに効く。
