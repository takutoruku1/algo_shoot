## 1. 尺の計算式（各案の秒数の根拠）

`src/Epilogue.cs:280` の実装がそのまま計算式:

```csharp
float rollEnd = (H + _roll.Length * RollLineH + 24f) / RollSpeed;   // H=216, RollLineH=17, RollSpeed=20
```

→ **`尺(秒) = (216 + 行数 × 17 + 24) / 20` ＝ `12.0 + 行数 × 0.85`**

1行増えるごとに **+0.85秒**。現行27行＝`12.0 + 22.95` = **34.95秒**。

> 注: 空行 `""` も `_roll` の1要素なので**尺を食う**（描画はされないが行送りは進む）。

## 6. 見栄えの工夫・懸念点・推奨

### 推奨: **案C（58行・約61秒）**
理由:
1. **尺が許容範囲**。案Bの1分34秒は、スキップ導線があるとはいえ**エンディングの余韻を殺す**。
   本作のロールは末尾に「そして、ご主人様へ。→ プレイヤーが送った言葉→ Thank you for playing.」という
   **作品の最重要の締め**があり（`src/Epilogue.cs:89-93`）、そこへ辿り着く前に飽きさせてはいけない。
   案Cの1分1秒なら、商業ゲームのロールとして自然な長さに収まる。
2. **セクション見出しがミナ色（Cool）で描かれる**（`src/Epilogue.cs:426-428`）ので、
   束ねるほど画面にリズムが出る。単調な名前の列が視覚的に分節される。
3. **必須のBGM表記（MusMus / PeriTune CC BY 4.0）を `── music ──` セクションに含められる**（§5-2(b)）。
4. 職種15は「ちゃんと作った感」が出る一方、同名連打が案Bほど滑稽にならない。

### 懸念点
- **⚠️ 案Cの列レイアウト問題**（§4 案C の注意点）。中央揃えレンダラなので、
  「職種を複数行 → 最後に名前」の体裁は実装時に調整が要る。
  この手間を避けるなら**案A**（1行1職種で完結・47秒）が最も安全。
- **⚠️ スキップ導線の表示時間**。`src/Epilogue.cs:439-445` の「長押しでスキップ」ヒントは
  「そして、ご主人様へ。」が画面下端に現れた時点で消える設計。行数が増えると**ヒントの表示時間も伸びる**だけで、
  ロジックは自動追従するので**コード修正は不要**（`tail` を `Array.IndexOf` で毎回引いているため）。
- **⚠️ `--shot` 撮影**。`src/Epilogue.cs:23-33` の `ShotHold` がロールのスキップを止めるので、
  ロールを伸ばすと `tools/EpilogueRollQa.cs` / スクショ撮影の待ち時間も伸びる。**QA側の想定秒数を要確認**。
- **⚠️ Codex の担当が証拠で裏付けられない**（§3-2）。現状は併記で逃げているが、
  **ユーザーが記憶で確定できるなら 🔸 印の行を単独表記に差し替えるべき**。
- **音楽セクションの位置**。案A〜Cとも `── music ──` を staff の後半に置いたが、
  §5-2(a) でクレジット画面への導線を作るなら、**ロール側は簡略化（サイト名のみ）**でもよい。
