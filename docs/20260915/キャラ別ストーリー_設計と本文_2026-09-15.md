# 第1部 設計

## 1. 絶対の制約（本文が守っていること）

- **ミナは一切登場しない**。who=1（ミナ）と who=3（ナレ）は全編で不使用。ナレ＝ミナ（[[narration-rule]]）のため、地の文そのものが存在しない。人物の声だけで語る。
- **三人はミナに救われた記憶を持たない**（心象世界の記憶は本人に残らない、が正典）。ミナへの言及・「救ってくれた誰か」への言及・「なぜ自分が変われたのか」への詮索は、全編に**一行もない**。彼女たちは変わった理由を知らないまま、変わった自分で生きている。
- FINAL（ミナの内側）は対象外。この3本は STAGE1／STAGE2／STAGE3 だけで進む（FINALはジョブに関わらずミナ本編固定）。
- 使用 who は **6=潜っているキャラ本人／2=相手ボス／4=投稿（本人の投稿・画面表示）** のみ。
  - **who=5（中継）は不使用**。Hud の話者ラベルが「あなた（ミナの声）」（`src/Hud.cs:438`）でありミナ不在の原則に反するため。本人が回線の向こうの「あなた」へ半分独り言で話す形（`CompanionDialogue.cs` チュートリアルの既存話法）で代替した。
  - who=0（あなた）も不使用＝このモードに下書き選択（ChoiceOverlay）は無い前提。

## 2. ビート構造（engineer との契約）

キャラごとの「章」は**そのキャラでのダイブ回数**で進む。章1=初回、章2=2回目、章3=3回目、4回目以降=ループ用の軽いセット。

| ビート | 行数 | 面依存 | 既存 step との対応目安 |
|---|---|---|---|
| 出撃時 | 2〜4行 | **非依存** | Intro 枠 |
| 道中の節目1〜3 | 各2〜3行 | **非依存** | MidPre/Mid・BossTalk・MidStory 枠 |
| ボス前 | 3〜5行 | **非依存** | MidEnd 枠 |
| 改心相当（山場） | 8〜15行 | **依存**（キャラ×面の9本） | Boss*.cs の Lines 枠 |
| 帰還時 | 2〜4行 | **非依存** | Clear 枠 |

**設計の要**: 章ビート（出撃／節目／ボス前／帰還）は「どの面に潜っても流れる」ため、**面の固有物（雨・教室・配信枠・ボスの語彙）を一切参照しない**。言及してよいのは三面に共通する要素（飛んでくる言葉・吹き出し・奥に誰かいる）だけ。面と噛み合う演技はすべて改心9本に集約した。ボス（who=2）が喋るのも改心9本の中だけ。

## 3. 章×面マトリクス

章の進行（縦）と改心（横）は独立。例:「あかり章2の状態で STAGE3 に潜る」と、章2の出撃〜帰還＋改心R3が流れる。

| 潜るキャラ＼面 | STAGE1（あふれるわたし） | STAGE2（我に返るわたし） | STAGE3（星逢レイ＝ガワ） |
|---|---|---|---|
| **あかり（灯し手）** | **R1** 自分の穢れ（特別回）——傘を持って連れて帰る | **R2** 「みんな」の名前・休む席の備品登録 | **R3** 会社用の顔の外し方・「中の人はいません」 |
| **こはる（祈り手）** | **R4** 返事のない側の画面もあったかかった | **R5** 自分の穢れ（特別回）——鏡はあたし | **R6** 同接「7」の右端の「1」。二年目の告白 |
| **レイ（語り手）** | **R7** 一行で三年生きた話・宛先は変えていい | **R8** 「またね」に日付はない・ファンに資格はない | **R9** 自分の穢れ（特別回）——泣く係と笑う係 |

対角線（R1・R5・R9）＝自分の面に潜った特別回。「自分の穢れ（過去の声）と向き合う」回として、他の6本と構造を変えてある（倒す相手ではなく、連れて帰る／鏡になる／再契約する）。

## 4. 各キャラのアーク要約

各章は `*StoryFilm.cs` の Aftermath（正典の到達点）から始まり、`Epilogue.cs` スタッフロール投稿の**手前**に着地する。到達点を追い越さない（再採点 2026-09-15 C項の指摘「救済済みの三人が自己分析済みの大人に均されている」への対処）。

### あかり（灯し手）——「待つ側」から「言う側」へ。取り消さずに送る練習
- 正典の起点: 一通を取り消さずに送った／転職相談の予約（土曜15:00）／紺の傘を返し、黄色だけ残った（`AkariStoryFilm.cs` Aftermath）。
- **章1**: 土曜の相談を控えた週。「一日ひとつ、引っ込めない」の練習。お守り＝消せなかった下書き（「……好きだよ。いまも。」の一行。**中身は最後まで言わない**）。八百円の傘を現実で買う（心象世界の小道具との無言の照応）。
- **章2**: 相談に行けた。会社で初めて「口で」言う（「それ、明日でもいいですか」）。向かいの席に中途の人が来ると知る。テーゼ「口で言うのの、いいとこ——取り消せないの」。
- **章3**: 話しかけた。声が小さくて聞き返され、昔なら「なんでもないです」だったところを、**もう一回言った**。スタッフロール投稿「向かいの席 中途の人来た 自分から話しかけた 既読とかない 顔見て言った」の一歩手前で終わる（投稿文は本編用に温存、ここでは踏まない）。
- 転職するかどうかは決めない（言う側になれたことが答えで、進路はプレイヤーに委ねる余白）。

### こはる（祈り手）——「見てるだけ」から「送る側」へ。画面のこちらから一歩出る
- 正典の起点: コメントにあと一行足した／途中で寝た／翌朝、隣の生徒に聞けた（`KoharuStoryFilm.cs` Aftermath）。
- **章1**: 隣の子と「遭難仲間」になる。頼ってばかりの負い目が顔を出し、「友だちって、割り勘じゃない」で自分を放す。
- **章2**: **母との会話の続き**。Memory で「途中で終わった昼休みの話」（`KoharuStoryFilm.cs:28`）の続きを一年越しに言う長距離回収。「しんどい日もある」→母は「そっか」だけ（親を悪役にしない正典を維持）。塾は「いまのままがいい」が通る。
- **章3**: **渡す側の一回目**。中学時代の自分の台詞「先に式を書き直すと、分かりやすいよ」（`KoharuStoryFilm.cs:14`）が二年ぶりに口から出る。テーゼ「送るとこまでが、あたしの番」。スタッフロール投稿「あと一行 足した」の手前に着地。
- レイとの結線は片方向のまま（章2で「地味だけど、好きだから」の告知をスクショ保存する＝見る側からの照応のみ）。

### レイ（語り手）——「ガワ」で守っていた人が「素顔」を少しずつ出す。配信の外の声
- 正典の起点: 「好きな作品を話す夜」を一件やり、ノートに初めて印（`ReiStoryFilm.cs` Aftermath）。
- **章1**: 「よかった」が二個来た。「二個で、次を出す気になった」＝数字との関係の回復。昼の接客の声と配信の声が混ざり始める。
- **章2**: **数字→名前**。常連を名前で呼ぶ。「同接7」を「名前が七個」と数え直す（スタッフロール投稿「名前覚えた」への橋）。ガワとは「半分こ」。
- **章3**: 正典の言い直し（「今日はちょっと、疲れてて……」「……なんて。そんなわけないでしょう。」`ReiStoryFilm.cs:30-31`）を**途中で止めて、訂正しない**。母が台所で配信を聞いていた（「台所の灯り」の好きな場面と無言で重なる。説明しない）。
- ガワは捨てない（正典: アバターを使い続けることが救済）。

## 5. 声の書き分け（再採点C項「思考の運びが三人とも同じ」への対処）

語尾だけでなく**思考の運び**を三人で変えた。全ビートをこの型で書いてある。

| キャラ | 思考の運び（構文の癖） | 例 |
|---|---|---|
| あかり | **言いかけて、止まって、言い切る**。取り消しの癖と戦う跡が構文に出る。数える癖→「数えない」と自分で放す | 「……あ、今の、取り消さない。行こう」 |
| こはる | **点数化してから、点数を捨てる**。数えかけてやめる。等身大の比喩（割り勘・遭難・電池） | 「三往復。……あ、また数えてる」 |
| レイ | **配信の声で言ってから、素の声で言い直す**（章3で言い直しをやめるのがアークの頂点）。命令形の優しさ | 「はいはーい、星逢レイ——……って、誰もいないか」 |

緩急: 全章ビートに最低1行の「緩」（軽口）を入れた（再採点D項「コンパニオン会話に笑える行がゼロ」への対処）。同一構文の三連（再採点G項）は排し、三人が同じ内容を言う箇所は作っていない。

## 7. 実装メモ（engineer への引き継ぎ）

1. **データ形状の提案**: `CompanionDialogue.Beat {Intro, Mid, Boss}` では足りない。新設を推奨:
   `enum SoloBeat { Intro, Mid1, Mid2, Mid3, PreBoss, Return }`＋`SoloStory.Chapter(Job job, int chapter, SoloBeat beat)`／`SoloStory.Redeem(Job job, string stageId)`。章カウンタはキャラ別ダイブ数（セーブ持ち。**改心到達（クリア）で進める**ことを推奨＝失敗ダイブは同じ章を再演）。
2. **who=6 の face が現状 Hud に無視される**: `Hud.cs:432-437` の `LineKind.Companion` は渡された portrait を捨てて spin スプライトで上書きする。本文の face を出すには「face 非空なら渡された画像を使う」変更が要る。使用 face は全て実在ファイル（下記8節）。
3. **既存 CompanionDialogue とミナ不在の衝突**: 現行 `CompanionDialogue.Stage()` はミナ行（who=1）込みで、決定2（ミナ本編の代わりにキャラの話）と両立しない。ステージ内ビートは本書のものへ**置換**（Menu 系の掛け合いはハブ側なので存続可。ただしミナ同席の是非は指揮官判断）。
4. **ミナ本編の装置のスキップ**: 下書き選択（ChoiceOverlay、who=0 前提）と、ミナ台詞を含む step（S1-4 束・S2 入力欄・S3 引用の嵐のミナ行 等）はソロモードでは発火させない。カメオ中ボスは戦闘として残してよい（本人行 who=2 のみ＝抵触しない）が、**あかりで STAGE1**（自分のカメオと遭遇）だけは違和感が残るため要判断。
5. **FINAL はジョブに関わらずミナ本編固定**（前提）。`CompanionDialogue.Final()` の who=3 二行は再採点 F項で違反指摘済み＝本書の範囲外だが統合時に要修正。
6. ループセット（4回目以降）は行数契約より軽い（出撃2・節目各1・ボス前1・帰還1）。抽選でなく順出しでよい。
