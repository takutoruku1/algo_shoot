- **ミナが一言も言わない**のは方針として正しい（`Hub.cs:240`「ミナは何も言わない」）。ただし、作中で最も感情的な出来事（救った人が隣に来る）を UI トーストだけで処理しているのは、演出として弱い。帰還会話（`ReturnDialog`）の末尾に**一行だけ**——ミナが数えるだけの行——を置く余地がある。
- **`Hub.cs:1994` の未解禁時トースト**「{CharacterName}は、まだ隣に立てない」は良い。「ロック中」ではなく世界の言葉で書かれている。

### 【R1】★★★ `CompanionDialogue.cs:201-202` — FINAL 導入に第三者ナレが新規混入

```csharp
(3, $"通信先：ミナの内側\n送信元：あなた / 同行する声：{name}", ""),
```

```csharp
(3, $"通信先：ミナの内側\n送信元：あなた / 同行する声：{name}", ""),
```

### 【R2】★★★ `CompanionDialogue.cs:31-180` — 54ブロックの思考の運びが同一

全ブロックが「同行者が気づきを述べる（1行）→ ミナが観測で受ける（1行）→ 同行者が前向きに締める（1行）」の三段固定。語尾は書き分けているが構文が同じなので、三面ぶん通すと maeda-pitfalls P1（構造が透ける）に落ちる。加えて三面とも「これは過去の声で、いまのあなたとは別」という同一説明を繰り返している（`:48` / `:98` / `:148`）。

**直し案**：
1. 「過去の声／いまのあなた」の説明は**あかり面 Intro の一度きり**に限定し、こはる面・レイ面からは削る（一度分かれば二度目は要らない。むしろ二度目の同じ説明が「作者が不安がっている」ように読める）。
2. 三段固定を崩す。最低限、**ミナが受けない**ブロックを各面1つ入れる（同行者が言って、ミナが数えるだけで終わる／同行者が2行続けて言う）。
3. 各面に**笑える1ブロック**を入れる。現状あかり面9ブロック中0。`Hub` の雑談（`:225-236`）が良く書けているので、あの呼吸をステージ内にも持ち込む。

### 【R3】★★ `Final.cs:176-179` — 決定打の直後に「ふふ」

```csharp
new() { Who = "ミナ",  Text = CueResolveLine },   // 「……その言葉。……ええ。届きました。」＝解決音と同時
new() { Who = "ミナ",  Text = $"……{word.Length}文字。……ふふ。相変わらず、短いですね。" },
```

前回【8】でこはる面について指摘された「決定打の直後を補足で汚す」が、作品最大の決定打である FINAL では未解決のまま。しかも「ふふ」は感情アーク上ここで出すこと自体は正しいので、**削るのではなく一拍ずらす**のが答え。

**直し案**：解決音の行の後に無音の一拍を置く。

```csharp
new() { Who = "ミナ",  Text = CueResolveLine },
new() { Who = "ミナ",  Text = "…………。" },                                   // ★追加（余白）
new() { Who = "ミナ",  Text = $"……{word.Length}文字。……ふふ。相変わらず、短いですね。" },
```

※ただし `CueSilenceLine = "…………。"` と本文一致で BGM 停止が発火する実装（`Final.cs:50`）なので、**この行を「…………。」にすると二重発火する**。`_cueSilenceDone` のワンショットで守られてはいるが、本文は別文字列（例「……。」）にするか、余白を演出側（`DropHold` 同様のホールド）で作ること。

### 【R4】★★ 三面の step 構成が同一 — 緩急の構造的天井

`StageAkari.cs:337-356` / `StageKoharu.cs` / `StageRei.cs:386-410` を並べると、あかり（カメオ前倒し）以外の二面は完全に同じ順序。台詞の質ではなく**会話が来るタイミング**が反復するので、二面目中盤で先が読める。これは D の 10/15 の天井を作っている最大要因。

**直し案**（低コスト順）：
1. **こはる面の入力欄（S2-4）をボス直前へ移す**。現状は道中の中程にあるが、`StageKoharu.cs:211-219` の「レイちゃんが|」が一文字ずつ消える演出は本作屈指の見せ場で、ボス戦直前の「溜め」に置いたほうが決定打（`BossKoharu.cs:141` の回収）との距離が近くなる。
2. **レイ面の QuoteStorm（引用の嵐）を面の頭に持ってくる**。レイの芯は「切り抜かれる恐怖」なので、面の開幕でいきなり貼られるほうが人格に合う。あかりのカメオ前倒しと同じ型崩しになる。

※これは台詞ではなく step 構成の変更なので、engineer 担当との共同作業になる。シナリオ側の判断としては「やる価値がある」。

## 6. 総括

前回指摘の**全17件＋構造指摘5件＋伏線3件が、ほぼ完全に実装へ反映されている**。特に感情アーク（B: 6→14）とナレの主体（F: 5→8）は、方針違反という性質の失点だったので、直った効果が大きい。FINAL の空洞（E）も埋まり、「構造は上等、クライマックスが空洞」という前回の講評はもう当たらない。

一方で、前回の採点後に入った**コンパニオン会話は、量に対して質が既存本文に届いておらず、かつ作品の一人称性という最大の強みを構造的に薄めている**。C と G を押し下げ、A と D の伸びを相殺した。ゲームデザインとしての価値は認めるが、シナリオとしては「入れたぶんだけ薄まった」が正直な評価で、83 という点はその相殺の結果。

次に一点だけ動かすなら、**【R2】コンパニオン会話の三段固定を崩し、各面に笑える1ブロックを入れる**こと。C・D・G が同時に動き、88 前後まで行ける。逆に、コンパニオン会話に手を入れないまま他を磨いても、85 あたりが天井になる。
