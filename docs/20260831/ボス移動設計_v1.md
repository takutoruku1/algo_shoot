# ボス移動設計 v1 — キャラの性格を移動パターンに翻訳する

- 作成: 2026-08-31 / game-designer（sakurai 準拠）
- 対象: `src/BossMover.cs` と `src/BossRei.cs` / `BossAkari.cs` / `BossKoharu.cs` / `BossMina.cs`
- 発端: 「ボスが中央で上下ふよふよ反転しているだけ。キャラ別の動きの違いがない」というユーザー指摘。**指摘は正しい**（§1 で実値を示す）。
- 方針: 移動は「表現」であって「難化」ではない。弾幕の数値・HP・難易度方針には一切触れない。

---

## 0. 前提（このゲームの移動幾何）

批評の土台として、位置取りがどう効くゲームかを先に固定する。

- 画面は内部解像度 **384×216**。自機は全域を動ける（`Player.cs:126-129`）。
- 自機の射撃は **水平（±1,0）のみ**（`Player.cs:224 ShotDir`）。つまり**ボスを撃つには自機がボスの Y 帯に並ぶ必要がある**。ボスの Y 移動＝プレイヤーの照準タスク、X 移動＝間合い（密着クリティカル 48px 以内 ×1.6、wiki/05_ゲーム仕様/06_ボス戦.md:27）。
- **ボスの移動設計とは「プレイヤーをどこに立たせたいか」の設計**である。ここが4ボスで同一なら、4戦の手触りは同一になる。

## 1. 現状の問題（3行）

1. **全ボスが同一の徘徊**。ゾーン中心 (200,70)±(90,28)・ランダム目標→イージング→0.25〜0.7s 休止→縦ホバー 3.5px/0.9Hz は `BossMover.cs:23-41` の既定値そのままで、4ボスの差は巡航速度 **42/40/38/38 px/s**（`BossRei.cs:11`, `BossAkari.cs:12`, `BossKoharu.cs:12`, `BossMina.cs:11`）——**最大 4px/s しか個性がない**。wiki も「徘徊」を全ボス共通の1節で書けてしまっている（`wiki/05_ゲーム仕様/06_ボス戦.md:40-42`）。
2. **リスクとリターンの「位置取り」レバーが死んでいる**（sakurai §2）。ランダム徘徊は読みを生まないので、プレイヤーは「ボスの Y をなんとなく追う」以外の位置判断をしない。密着クリ 48px・グレイズ・レイの逃げ腰圧という「前へ出る動機」が既にあるのに、ボス側の動きがそれに応答しない。
3. **キャラ表現・記憶の損失**（sakurai §11「挙動の差で個性を立てる」）。レイの傲慢もあかりの縋りもこはるの「とまれない」も、弾の色と台詞でしか語られず、**動きは4人とも同じ幽霊**。ボス戦の記憶がスペル名でしか残らない。

## 2. 共通ガードレール（全ボスに適用）

`BossMover.cs:12-17` の既存原則「激しい揺れは視覚（VisualOffset/Lean）へ、当たり判定の中心はゆっくり素直に」は**全案で維持**する。追加で：

| # | ガードレール | 値 |
|---|---|---|
| G1 | SHIELDED 中（弾を撃っている間）の判定中心の速度上限 | **90 px/s**（演出ダッシュ＝非発射中のみ例外。あかり通路の 320px/s は現行維持） |
| G2 | 自機との最低距離 | **90 px**（ミナは 110 px）。割りそうなら推進を止める。接触被弾の理不尽（sakurai §7）を構造で断つ |
| G3 | スパイラル系（連続糸）発射中の移動 | **等速直線 60 px/s 以下 or 停止**。発射原点が乱れると糸が読めなくなる（視認性） |
| G4 | AOE / テレグラフ詠唱中（`AreaSpellCaster.AoeActive` 等） | **その場ホールド**。安置円の「ボスから60px除外」（06_ボス戦.md:60）を移動で裏切らない |
| G5 | EXPOSED（無防備窓 4s）中 | 巡航速度 **×0.5**。ご褒美時間に横並びの照準合わせで消耗させない（親切設計。現行は窓中も通常徘徊） |

G5 だけは全ボス共通の「手触り改善」であり、キャラ表現とは独立に効く。

## 3. ボスごとの移動デザイン

### 3.1 レイ 「常に“上”を取る。攻めない相手には、降りてきて詰める」

傲慢＝序列。**位置の上下がそのまま順位**。プレイヤーの上を取り続け、逃げ腰圧（`BossRei.cs:43-53`）が動きにも現れる。

**基本移動（TrackAboveY）**
- Y: `clamp(自機Y − 34, 46, 92)` を追従（常に自機より 34px 上＝「あなたの上にいる」）。追従の時定数は 0.45s（ぬるっと張り付く）。
- X: 150〜280 の帯を**直線・キビキビ**移動。巡航 42→**55 px/s**、accelTime 0.55→**0.30**、休止 0.25-0.7→**0.6-1.0s**（移動→ピタッと静止の「言い切り」＝Q.E.D. の句読点）。ホバー振幅 3.5→**2.0**（ふよふよではなく凛と浮く）。
- リスクとリターン: レイを撃つには自機が**上へ**（＝ボスゾーンへ）踏み込む必要がある。上に行くほどリング弾の密度圏＝リスク、密着クリ圏＝リターン。

**逃げ腰圧との連動（本案の核）**
- `_pressure` 0/1/2 に応じて上オフセット **34 → 18 → 6 px**、巡航 55→48（ゆっくり歩み寄る威圧）。「戦ってよ。わたしを、ちゃんと見てよ。」（`BossRei.cs:61-64`）が**距離で見える**。1 ヒットで圧が緩む既存仕様（`OnPlayerDealtDamage`, `BossRei.cs:221-224`）＝攻めれば離れてくれる、が空間の因果になる。

**スペル/終盤の変化**
- 第4スペル「孤高の王座」(HP26%〜) とフィナーレ: **玉座モード** — (200,48)±(60,4) を横移動のみ 30px/s。最上段に固定＝孤高の画。スパイラル原点が安定し G3 も満たす。
- 安置リレー「最終選考」中（`AoeGateActive`）: (200,60) ホールド（G4）。

**衝突しないことの確認**
- 安置リレー: 安置は自機基準で置かれ（06_ボス戦.md:60）、ボスはホールドするので現行より安全側。圧タイマーは SHIELDED 中のみ進む既存ゲート（`BossRei.cs:203`）も不変。
- 自機狙い扇（3〜7way）: 発射位置が近づくのは圧 1〜2 のときだけで、G2 の 90px 下限があるため反応時間の下限は 90/98px/s ≒ 0.9s を維持。

**実装の当たり**: `BossMover` に `TrackAboveY` モード＋自機位置の注入（`Step(pos, delta, playerPos)` オーバーロード）。パラメータ切替は `ApplySpell()`（`BossRei.cs:76-82`）と `TickPressure` からの再 Configure で足りる。**サブクラス不要**。

### 3.2 あかり 「距離感の壊れた幼なじみ——縋って詰めて、我に返って突き放す」

愛の洪水と「来ないで」。**接近↔急離脱の振り子**が、縋りと自責の往復をそのまま描く。

**基本移動（Pendulum、周期 ≒ 7s）**
- 接近相 4s: 自機へ向けてじわっと寄る。初速 42、+5px/s² で **最大 70 px/s**（縋るほど加速）。下限距離 **90px**（G2）、Y は 118 まで（降雨扇の前提「上から」を守る）。
- 突き放し相 0.8s: 反対側の上隅へ **160 px/s** で離脱（「来ないで……っ」）。**この 0.4s は発射を止める**（G3 相当の視認性ガード＋演出の一拍）。
- 静止相 1.2s: 俯いて漂う。ホバー振幅 3.5→**5.0**、周波数 0.9→**0.7Hz**（雨に濡れた重さ）。
- リスクとリターン: 接近相は密着クリ圏とグレイズ機会が向こうからやってくる。特にキミ弾スペル（「ずっと一緒」「離さない」`BossAkari.cs:248-268`）は**近いほどグレイズで弾が和らぐ**既存ギミックと噛み合う——「触れると距離がほどける」が移動でも成立する。
- 例外: 第2スペル「すきって言って」（全方位リング）中のみ接近下限 **120px**（リングは近距離だと下方の抜け道が消えるため）。

**スペル/終盤の変化**
- フィナーレ（最後のバー50%）: 突き放し相が消える＝**「離さない」を動きで**。常時接近、ただし下限 **110px**・速度上限 60（難化させないための緩和とセット）。

**衝突しないことの確認**
- 通路「雨の帰り道」: 現行の再 Configure によるダッシュ退場/帰還（`BossAkari.cs:168, 175, 189`）は `Hold(ダッシュ先)` モードにそのまま写像できる。**API（Configure で上書き→戻す）を維持**し、通路フェーズ中は Pendulum を凍結。
- 下向き扇（±40°）: Y 上限 118 で「自機より上から降る」前提を保証。

**実装の当たり**: `Pendulum` モード（接近/離脱/静止の3相ステートを Mover 内に持つ）。通路との切替があるので、`BossAkari` 側は `_corridorPhase` に応じて Mode を切るだけ。**サブクラス不要**。

### 3.3 こはる 「台所の定位置を守る。動きは小刻み、移動は“段取り”どおり」

家事の人は浮遊しない。**コンロ・まな板・配膳台の3定位置**に立ち、手だけがせわしない。ランダム徘徊を捨てて**唯一の「読めるボス」**にする＝4人の中の緩急（sakurai §3）。

**基本移動（Stations）**
- 定位置3点: **(140,74) / (200,66) / (260,74)**。滞在中は移動せず、**小刻みの所作**だけ: ホバー 0.9→**1.7Hz**・振幅 3.5→**1.6**、0.5s ごとに ±5px の X シャッフル（まな板トントン。将来 SE 同期の余地）。
- 定位置の切替は**スペル切替（HP 78/50/26%）と同時**、直線 **90 px/s**・lean 0.16→**0.22**（歩いて移動する前のめり感。非発射の移動なので G1 例外でも可だが 90 で足りる）。
- リスクとリターン: 位置が読める＝当てやすい最易のボス。その代わりスペル側が「自機の現在地」を撃つ（五徳の十字火・包丁の軌跡・アンカー付きテレグラフ）——**「彼女は止まり、あなたが動かされる」**の対比がキャラそのもの。

**スペル/終盤の変化**
- 「お残し禁止」(HP52%): 配膳後は **(150,56) でホールド**——画面右半分の食卓（x214-356・y44-84、`BossKoharu.cs:310-321`）を**空けて見守る**。
  - ⚠ **現行の実害**: meal 中も徘徊は続き（`BossKoharu.cs:203-211`）、徘徊帯 x110-290 が食卓 x214-356 と **x214-290 で重なる**。食べに前へ出た自機の進路にボスの接触判定が漂う理不尽が構造上あり得る。本案はこれを直す（表現と親切設計が同時に立つ）。
- 「五徳の十字火」・包丁テレグラフの詠唱中: **完全停止**（火を扱うときは動かない＝キャラ表現であり G3/G4）。
- フィナーレ（≤18%、`_finaleCap`）: **「とまれないわたし」の文字通り化**——シャッフル周期 0.5→**0.25s**、さらに 6s ごとに3定位置を **60 px/s** で連続巡回（等速直線＝スパイラル原点も読める。G3 充足）。止まれていた人が止まれなくなる、を最後に見せる。

**衝突しないことの確認**
- 定位置 Y 66-74 は投稿弾・祈り弾扇の既存レイアウトと干渉しない（発射原点が現行徘徊帯の内側に収まるため弾幕の到達域は不変）。
- meal ホールド位置 (150,56) は食卓左端 x214 から 64px 離れ、G2 も自機が右半分にいる間は自明に満たす。

**実装の当たり**: `Stations` モード（点列＋滞在。実体は `Hold` の点リスト切替）。`ApplySpell()`（`BossKoharu.cs:101-107`）と `_mealPhase`/`_gotoPhase` からの Mode 切替のみ。**サブクラス不要**。

### 3.4 ミナ 「三人の残響が順番に憑依する——最後に、はじめて“ミナ自身”が浮かぶ」

FINAL は融合スペル（『レイの渦＋あかりの雨』…）と背景クロスフェード（HP 80/58/36/16%、`MinaRoot.cs:88-116`）が既に「三人の混線」で組まれている。**移動も同じ閾値で憑依させる**。3戦で学んだ動きの読みがそのまま通用する＝ラスボスでの回収（sakurai §9・§11）。

**基本移動（憑依リレー、背景と同じ HP 閾値）**
- HP 100〜58%: **レイ型** TrackAboveY（オフセット 30・巡航 50・ピタ止め）。
- HP 58〜36%: **あかり型** Pendulum（下限 **110px**——5way 104px/s の自機狙いがあるため近接は甘くしない）。
- HP 36〜16%: **こはる型** Stations 3点（パネル軌道 32 なので間隔広めに (130,70)/(200,62)/(270,70)）。
- HP ≤16%: **ミナ固有** — (200,64) ホールド、ホバー振幅 **6.0**・周波数 **0.45Hz**（大きくゆっくり）。**「中央でふよふよ浮く」は削除ではなくここへ隔離する**——4戦目の最後に初めて出る静かな浮遊が、「奥にいる本当のミナ」の主題になる。フィナーレのスパイラルも原点固定で読める（G3）。
- 切替の瞬間: 0.3s のグリッチ痙攣を **VisualOffset のみ**に入れる（判定は動かさない。既存の詠唱身震い `BossMina.cs:127-134` と同じ作法）。

**衝突しないことの確認**
- 全画面 AOE 3回（62%/42%/フィナーレ）: 既存どおり `AoeActive` 中は通常弾停止＋詠唱モーション。移動も**ホールド**（G4）にするだけで、安置配置ロジックに触れない。
- こはる型区間はスパイラル（心象の核、Di0.075）と重なるが、Stations は静止主体＝ G3 充足。

**実装の当たり**: 新規モードなし——**他3ボスの primitive をHP閾値で切り替えるだけ**。`OnHpChanged`（`BossMina.cs:222-247`）に既にある閾値処理へ Mode 切替を足す。展開コストが最小になるのは実装順の恩恵（§5）。

## 4. やらないこと

- **弾幕の数値には触れない**。弾速・弾数・間隔・HP・難易度倍率（`Dn/Di`）はすべて現行のまま。移動で回避難度を上げない（あかりの接近には下限距離、レイの降下には圧という自業自得のトリガーを必ず挟む）。
- **テレグラフ・安置の視認性を守る**。詠唱中ホールド（G4）、スパイラル中の等速・低速（G3）、突き放し中の発射停止（あかり）で「読めない原点移動」を作らない。
- **判定中心の急動をしない**。派手さは VisualOffset/Lean 側（`Enemy.cs:647-657 ApplyBossMotion`）に寄せる既存原則を全モードで維持。
- **中ボス（CameoBoss）とヒカゲ（未使用）は変えない**。カメオは現行 Roam のまま＝「本戦で動きが化ける」落差を残す（§15 密度の集中）。
- **移動モードを増やしすぎない**。primitive は **Hold / Roam / TrackAboveY / Pendulum / Stations の5つで打ち止め**。ミナは新規を足さず合成で作る。

## 5. 段階案

**Phase 1 — レイで最小実装（推奨）**
1. `BossMover` に Mode enum＋`Hold`/`TrackAboveY` を追加、`Step(pos, delta, playerPos)` オーバーロードで自機位置を注入（ボス側は既に `AimAtPlayer()` で取得済みの座標を渡すだけ）。
2. `BossRei` を接続: 基本 TrackAboveY／圧で降下／王座モード／リレー中ホールド／G5。
3. 検証: `qa-autoplay`（進行不能・接触被弾率・ボス-自機最小距離のログ）→ `demo-video` で手触りと「圧で降りてくる」画の確認。
- レイを先にする理由: 逃げ腰圧という**既存の攻め動機と直結**して効果が一番測りやすく、固有ギミック（リレー）が「ホールドするだけ」で最も干渉が少ない。

**Phase 2 — 全ボス展開**
4. `Pendulum`（あかり）→ `Stations`（こはる。meal 中の食卓重なり修正を含む）→ ミナ（既存 primitive の閾値切替のみ）。
5. 仕上げ: G5（EXPOSED 減速）を全ボス適用、wiki `06_ボス戦.md` の「徘徊」節をボス別に書き分け。

## 6. 期待する体験の変化（お客様目線）

- 初見: 「レイは上から見下ろしてくる」「あかりは寄ってくる、怖い、でも近いと稼げる」「こはるは台所から動かない」——**言葉にできる違い**が1戦目から生まれる。
- 上級者: レイ戦は圧管理＝距離管理、あかり戦は接近相の密着择、こはる戦は定位置読みの安定周回、と**攻略の型が4通り**になる。
- FINAL: 3つの型が順に還ってきて、最後に静かな浮遊だけが残る。**「ふよふよ」が欠点から主題に変わる**。
