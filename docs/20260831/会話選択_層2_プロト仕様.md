## 5. 収束確認

A/B どちらの最終行の後も、現行 MidStory の末尾2行（`src/StageKoharu.cs:169-170`）を**共通部（MidStoryPost）としてそのまま**再生してから戦闘再開する:

> [少年] ……その祈りは、ちゃんと届いてたって。それだけ、伝えるんだ。もうすぐ、そこまで来てる。
> [ミナ] ……ご主人様。お声に、また、ノイズが。
> → 戦闘再開（02_script_dump.md §7-10:803 の現行フローどおり、step16→11 復帰）

- Aから: ミナが引いた沈黙を、少年がボスへ向き直る現行行で受ける＝自然に接続。「また、ノイズが」はAの針飛びの直後でも「また」で辻褄が合う（異常が平常の声にまで残っている、という上乗せ）。
- Bから: 現行と同一の並び（168→169→170）に1行挟まっただけ＝正典のまま。

## 8. フラグ名の提案

```csharp
// GameManager（/root/Game）に追加
public bool PressedTheQuestion;   // STAGE3 MidStoryで選択A「もういちど、聞く」を選んだ（=もう一度踏み込んだ）
```

- **意味**: true = A選択。false（既定）= B選択またはプロト導入前のセーブ＝現行台詞（後方互換）。
- **記録タイミング**: 選択確定の瞬間（分岐配列の再生開始前）。
- **永続化**: `GameManager` の既存セーブ辞書（`GameManager.cs:827` 付近の `data[...]`）にキー `"pressedQ"` で保存推奨。エピローグはリトライ・再起動を挟み得るため、セッション内変数だけでは落ちる。
- MidStory は一度しか発火しないため再上書きの心配はない。リセット（ニューゲーム）時は他フラグと同様にクリア。
