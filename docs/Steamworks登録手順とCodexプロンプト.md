# CodexでSteamworksのチェックリストを登録する手順

対象は、SteamworksにゲームのAppIDがあり、ストアページと配布ビルドを初めて登録する開発者です。ゲームのプロジェクトをCodexで開き、自分でSteamworksにログインし、対象ゲームの管理トップを開いてください。まず「1」を貼り、結果に応じて必要な番号だけを同じチャットで使います。すでに登録した作品でも途中から再開できます。

## 1　対象を指定し、現在地を確認する

次の枠が最初に貼るプロンプトです。山括弧を自分の作品の値に置き換えてください。未定の値は「未定」、使わない機能は「対象外」で十分です。パスワード、Steam Guardのコード、税務・銀行情報は入力しません。

```text
Steamworksのチェックリスト登録を、画面を操作して手伝ってください。
ゲーム名：〈タイトル〉
AppID：〈対象アプリの数字〉
プロジェクト：〈ゲームのフォルダー〉
公開する開発元名・パブリッシャー名：〈それぞれの名称〉
公開するサポート窓口：〈専用メールまたは問い合わせURL〉
ゲーム内の対応言語／ストア説明を書く言語：〈別々に指定〉
発売目標日・ストア上の表示・販売価格：〈決まったものだけ〉
審査候補の版・配布ファイル：〈版とパス。作成中なら「作成中」〉

Steamworks → アプリ管理 → 対象ゲームから作業してください。
子画面に移ったらタイトルとAppIDを照合し、デポやパッケージはそのアプリから開いてください。
最初は読み取りだけで、ストアとビルドのチェックリストを「必須／推奨」「完了／未完了」に分け、
次に進める項目と、私にしか決められない項目を示してください。
以降、私が指定した項目は下書き保存まで進め、再読み込みで確認してください。
価格申請、Steamworks設定の公開、配信ブランチの変更、審査提出、一般公開は個別の指示を待ってください。
作業に使うのはこの作品のファイルだけ。スクリーンショットやログを外部に共有しないでください。
```

**番号の見分け方。** AppIDはゲーム、Depot IDは配るファイルのまとまり、Package IDは販売・アクセス権の単位、Build IDはアップロードしたビルドを識別します。ストア編集URLの数字がAppIDと異なる場合もあります。番号を推測してURLを組み立てず、管理トップからたどると別作品への誤登録を防げます。

## 2　ストアの基本情報とコンテンツを登録する

```text
対象ゲームの現在の実装・プレイ画面を根拠に、ストアの短い説明と詳細説明を指定言語で起草してください。
承認した文面、開発元・パブリッシャー、公開用サポート窓口を「ストアページを編集」で登録してください。
OS、ゲーム内の言語（UI・音声・字幕）、プレイ人数、ジャンル・タグ、コントローラー、
アクセシビリティは発売ビルドで使えるものだけ選んでください。
Windows要件はCPU・メモリ・GPU・必要容量ごとに、動作確認した環境、実測値、未確認を示し、
根拠のある欄だけ記載してください。対応言語ごとにストアプレビューを確認してください。

コンテンツアンケートは、全年齢向けに見える場面だけで判断せず、ゲーム全体の台詞・映像・同梱素材、
生成AIの利用実態を確認し、回答案と私に確認が必要な点をまとめてください。私の確認後に登録してください。
```

ストア説明を英訳してもゲーム本編の英語対応を意味しません。コントローラーのフルサポートを選ぶ前に、起動後のメニュー・設定・プレイ・終了を通して実機で確認します。開発PCの仕様は「この環境で動いた」という記録に使い、最低スペックには検証した値を使います。必要容量はZIPの圧縮サイズと区別して、インストール後の容量から決めます。

生成AIの申告では、プレイヤーが見る・聞く同梱コンテンツの制作時の利用と、プレイ中の生成を分けます。台詞・画像・音声・翻訳などを棚卸しし、プレイ中に生成する場合は実際の対策も確認します。[Valveのコンテンツアンケート](https://partner.steamgames.com/doc/gettingstarted/contentsurvey?l=japanese)

## 3　ストア画像とゲームプレイ予告編を登録する

```text
使ってよい素材は〈素材フォルダー〉です。「ストアページを編集」で各画像枠の現行仕様を確認し、
ストアカプセル、ライブラリのカプセル・ヒーロー・ロゴ、ゲームプレイのスクリーンショット、
ゲームプレイ予告編の順に、ファイル名・登録先・不足素材を一覧にしてください。
指定したファイルだけを正しい枠に登録し、スクショの順番と予告編の名前・種類・言語を確認してください。
ドラッグが私にしかできないときは、該当のドロップ欄を開き、ファイルのフルパスを教えてください。
ドラッグ後は保存と動画変換を確認し、ストアのベータプレビューで画像と動画の再生を確認してください。
```

スクリーンショットは実際のプレイ場面を5枚以上、16:9・1920×1080以上で用意します。通常のストアカプセルは小さく表示しても作品名が読める絵にし、ライブラリのヒーローは文字なし、ロゴは透過背景にします。最初の予告編は、冒頭から操作とゲーム内容が伝わる実プレイが適しています。[ストア画像](https://partner.steamgames.com/doc/store/assets/standard?l=japanese)・[ライブラリ画像](https://partner.steamgames.com/doc/store/assets/libraryassets?l=japanese)・[予告編](https://partner.steamgames.com/doc/store/trailer?l=japanese)

## 4　発売予定日と価格を決める

```text
発売目標日は〈年月日・タイムゾーン〉、購入者に見せる表記は〈近日登場／指定日など〉です。
指定済みの日付と表示形式は保存し、管理画面の目標日と、ストアのベータプレビューに出る表記を見せてください。
未定なら保留してください。
販売形態は〈有料／無料〉です。有料の場合は対象の販売パッケージを確認し、
希望価格〈通貨・金額〉を基に、Steamの換算案を含む地域別価格表を提示してください。
価格表を確認したら、私が「この表で価格申請」と返した時点で申請し、申請中か承認済みかを報告してください。
```

Steam内部には具体的な予定日を登録し、購入者向けには「近日登場」などの表示を選べます。予定日の2週間前に入ると通常の画面から日付を変更できません。地域価格の提案は選択した米ドル価格が基準なので、日本円の希望額と海外価格を並べて確認します。発売後の価格変更は原則30日を過ぎてからで、いずれかの通貨を値上げすると、その後30日間は割引が制限されます。[発売予定日](https://partner.steamgames.com/doc/store/release_dates?l=japanese)・[価格設定](https://partner.steamgames.com/doc/store/pricing?l=japanese)

## 5　配布ビルドを登録し、Steamから起動する

```text
審査候補は〈版〉、配布ファイルは〈パス〉です。プロジェクトの出力規則を読み、配布物内の起動ファイル、
必要なライブラリ・ライセンス、Steamworksの起動設定（OS・相対パス）、デポとパッケージを照合してください。
開発用steam_appid.txt、セーブ、ログ、キー、テストデータが配布物に混ざっていないことを確認してください。
中身と対象Depot IDを示し、指定した版だけをアップロードしてください。別作業でビルド中なら旧版は使わず待ってください。
Webアップロードでは転送完了、デポ作成完了（Manifest ID）、Commit後のBuild IDを順に確認してください。
ブランチ変更は、新旧Build IDと配信先を提示し、指定されたブランチだけに反映してください。
Steamクライアントで更新後のBuild IDとゲーム内の版を照合し、ライブラリの［プレイ］から起動・プレイ・終了を確認してください。
```

Webアップロードで「Building depot done」と出た段階はデポの作成完了です。続いてビルドを確定し、配信先に目的のBuild IDが表示されて初めてクライアント側の確認へ進めます。Refrainでは新しいビルドを設定した直後にも、Steamで起動するとタイトルに旧版が表示されました。同じZIPを再送する前に、配信ブランチ → クライアントの更新 → 実際に起動したファイルの順に照合します。発売済み作品ではdefaultへの反映で購入者にも更新が届きます。Web画面の容量制限を超える場合はSteamPipeのSDKツールを使います。[Steamへのアップロード](https://partner.steamgames.com/doc/sdk/uploading?l=japanese)・[ビルドと配信先](https://partner.steamgames.com/doc/store/application/builds?l=japanese)

## 6　採用した機能だけ実績とクラウドを検証する

**Steam実績を使う場合**

```text
このゲームの実績について、解除条件・ゲームコードのAPI名・Steamworks側のAPI名・表示名・説明・アイコンを照合してください。
Steamworksに定義を保存し、反映が必要な差分を見せてください。公開の指示後、Steam経由の対象ビルドで
実際に条件を満たし、Steamの実績一覧に解除が記録されたことを確認してください。
動作確認後はストアの「基本情報 → 対応している機能 → Steam実績」を有効にして保存してください。
管理トップを再読み込みし、推奨欄の未完了表示が消えたか報告してください。
```

Refrainではゲーム内で実績が解除できても、ストア側のチェックを保存するまで推奨項目が残りました。**解除の記録**と**ストア上の対応表示**の両方を確認するのがポイントです。[Steamの実績](https://partner.steamgames.com/doc/features/achievements?l=japanese)

**Steam Cloudを使う場合**

```text
配布版が実際に書き込むセーブの場所とファイル名を確認してください。Auto-Cloudを使う場合は
ルート・サブフォルダー・ファイルパターン・対象OS・容量・件数の設定案を示してください。
対象はゲーム進行の復元に必要なファイルに絞り、ログや端末固有の設定は除外してください。
差分の確認・公開後、テスト用スロットで保存して正常終了し、そのAppIDのcloud_log.txtで
終了後のアップロード成否と対象ファイルを確認してください。別環境への復元テストの結果は別に記録してください。
確認できたらストアの「Steamクラウド」表示を保存してください。既存の利用者セーブは保護してください。
```

RefrainのWindows版では、インストール先の `SaveData/Progress` にある `save_*.json` と `read.json` が対象でした。終了後の同期を確認し、別PCでの復元は未確認として記録しました。他作品ではまず配布版で保存場所を実測してください。[Steam Cloudの設定と検証](https://partner.steamgames.com/doc/features/cloud?l=japanese)

## 7　審査に提出する

```text
管理トップで、ストアとビルドそれぞれの必須項目・審査状態を確認してください。ストアのベータプレビューと
配信ビルドを照合し、言語、対応OS、機能、画像、予告編、価格、コンテンツ申告の矛盾を挙げてください。
ビルドについてはdefaultのBuild ID、Steamからの起動結果、開発PC以外でのテスト結果を示し、
最終確認画面の各項目に事実どおり回答できるかを確認してください。未検証事項は保留してください。
提出可能なら、対象・審査メモ・提出後の状態を示してください。
私が「ストア審査に提出」または「Build ID ○○をビルド審査に提出」と指定した方だけを提出し、
管理トップの「レビュー待ち」などの表示と提出日を確認してください。
```

順番は **ストア審査に提出 → ビルド審査に提出** です。ストアを先に提出すれば、ビルド審査の準備を進められます。審査は通常それぞれ3～5営業日で、修正を見込んで希望日の少なくとも7営業日前に提出します。承認後の「近日登場」の公開と、ゲームを発売する操作はそれぞれ別です。通常は発売前に「近日登場」で少なくとも2週間の公開が必要です。[審査](https://partner.steamgames.com/doc/store/review_process?l=japanese)・[リリース手順](https://partner.steamgames.com/doc/store/releasing?l=japanese)・[近日登場](https://partner.steamgames.com/doc/store/coming_soon?l=japanese)

**審査ボタンを押せない場合。** Refrainの有料版では、価格未登録とストア審査への未提出がビルド提出時に問題になりました。管理トップと提出画面に表示される自作品の条件を確認し、該当する項目から解決します。審査結果は管理トップから開けるSteamworksサポートのチケットで確認できます。公開用の問い合わせアドレスと審査通知の宛先は区別してください。

**PCが1台の場合。** Refrainのビルド提出画面には、開発PC以外にSteamからインストールしてテストしたことを確認する項目がありました。開発PCでのプレイ時間や実績解除は別PCでの検証には使えません。別のPCでテストできる担当者に依頼するか、用意できる環境で条件を満たせるかSteamworksサポートに確認し、その間はストア審査など独立した作業を進めます。

## 中断した作業を再開するとき

```text
対象は〈ゲーム名・AppID〉です。管理トップから再開し、前回の記録と現在の画面を照合してください。
ストア・ビルド別に「どこまで保存／提出したか」「実機で確認したこと」「次の一手」を示してください。
転送中のファイルや審査中の申請がある場合は、その結果を先に確認して重複登録を防いでください。
```
