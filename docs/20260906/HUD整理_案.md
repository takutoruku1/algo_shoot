# 画面レイアウト刷新の案（HUD整理 → プレイ領域とUIの分離）

**2026-09-06 / game-designer 査定 ＋ 指揮官の決定**

## 0. 何を解く問題か

ユーザーの実機所感（要点）: 「プレイしているところに画面 UI が重なりすぎていて、敵の攻撃がかぶって分からなくなる瞬間がある。プレイしている画面サイズを変更して、必要な UI をシューティング画面の外側に出したい」。

これは視認性の問題で、難しさではなく不親切。実装がそれを自白している。`src/Hud.cs:163-180` に「左上HUDの自動退避」という専用機構（`TopLeftFadeMin=0.18` / `TopLeftHoldDur=0.6`、ヒステリシス付き）があり、レイアウトの負債を実装で埋めている状態。根本解は「重ねない」しかない。

本案の主眼は「弾と UI を原理的に重ねない」。消す（心・人数・やさしさ・救った人・汚染・グレイズの副次効果）は前提として実行しつつ、残す UI は全部プレイ領域の外へ出す。

## 2. プレイ領域の新しい寸法

内部解像度 384×216 は変えない（`project.godot` は触らない）。フィールド矩形だけ定義する。

| 値 | 設計座標(1280×720) | 内部座標(384×216) |
|---|---|---|
| サイドパネル | x 0 → 373 | x 0 → 112 |
| 隙間（額縁） | x 373 → 400 | x 112 → 120 |
| プレイフィールド | x 400 → 1280, y 0 → 720 | x 120 → 384, y 0 → 216 |

- 上下は削らない。横スクロールなので縦を削ると弾の回避余地が減り難易度が直接上がる。
- 112px はライフ最大6と BOMB が横に収まる最小幅＋余白。現状の左上パネル幅より広いので文字を大きくできる。
- 264:216 ≒ 1.22:1 は既存の弾幕を作り直さずに済む上限。
- 右端（x=384）は動かさない。敵の湧きと弾の破棄が右基準のため。

却下: 左右両側に帯（フィールドが狭すぎる）、上下も削る（難易度の全面再調整＝規模 L）、内部解像度の変更（カットシーンが全部壊れる）。

## 4. 会話バー・ボスバー・スペルカード

原則: 弾が飛んでいる間ずっと出ているものだけを外に出す。一過性・戦闘停止中のものは重ねてよい。

| 要素 | 決定 | 理由 |
|---|---|---|
| 会話バー | 重ねたまま。`x=400, w=840` へ寄せる | 会話中は敵も弾も止まる（`BubblePaused` で `ClearEnemyBullets` まで走る） |
| ボスバー | プレイ領域上端に残す。中心へ寄せ、高さ 60→44、y 60→8 | ボスの真上にあってこそ読める。上部は元々弾が薄い |
| スペル宣言カード | 重ねたまま。中心へ寄せる | 見せ場のピーク。5秒だけ・直後は弾が薄い |
| ボス字幕 | 重ねたまま。中心へ | 攻撃可能窓の告知。下端で短命 |
| バナー・リザルト | 全画面のまま | 戦闘が終わっている |

これで恒久的にプレイ領域に居座る UI はボスバー1つだけになり、`TopLeftFade` 一式が不要になる。

## 5. やさしさ：機能ごと撤去

表示だけ消すのは却下（見えないのに Ctrl で突然連射が速くなる＝原因を理解できない挙動）。

外れるもの: Ctrl の全開（5秒）、全開中の連射1.57倍と弾道強化、発動時の局所浄化、金の二重リング、トーストとSE、汚染による溜まり鈍化、道中の選択の +0.02、中ボス撃破の +0.6、祈り弾・病みポスト・帳の加算、チュートリアル1ステップ、遊び方の説明、QAパイロットの Ctrl 送出。

壊れない導線（実装で確認済み）:
- **連鎖浄化は無関係**。`Ripple.cs` はやさしさも `IsOverload` も参照しない。常時オンのまま。
- ショップ強化はどれも `IsOverload` を参照しない。説明文1箇所のみ。
- `_kindFill` はセーブに入っていない。互換の心配なし。

代替: 選択の +0.02 → スコア +500。中ボスの +0.6 → `CameoScoreReward` 900→2000。全開の役割はボムと回避よけに寄せる（追加実装なし）。

## 6. 汚染：表示だけ消す・値は残す

値が効いている先: 画面の濁り（`MurkVignette`）、BGM の濁り（`Audio.cs:262`）、ハブの演出、FINAL の 1.0、各面の入場値、（送らない）の +0.02、`ContaminationGainMul`。すべて維持。バーが無くても画面自体が語る。

値の簡略化は却下。最優先テーマは「ヒロイン3人の闇の解消」で、汚染はその可視化。選択が世界を濁らせている事実は残す。

## 7. グレイズ：スコア加算だけにする

現状 `AddGraze` は4つを同時にやっている（スコア10／`GrazeCount`／やさしさ+0.07／インプレ+1／コンボ猶予）。

| 効果 | 変更後 |
|---|---|
| スコア | **10 → 30**（他を剥がすと旨味が 1/4 になり引き撃ちが最適解に戻るため） |
| `GrazeCount` | 維持（統計のみ） |
| やさしさ | 削除 |
| インプレ | 削除 |
| コンボ猶予 | 削除 |

回避よけ（`AddDodgeGraze`）は**やさしさぶんだけ削除**し、スコア50・インプレ2・コンボ猶予は残す（指揮官決定）。回避は CD 0.8秒を切って弾に突っ込む別リスクで、痩せさせすぎると使う理由が消える。

グレイズのリング・閃光・SE は残す。手応えは情報量の問題ではない。

## 8. サイドパネルの中身

設計座標 x 0 → 373。見る頻度が高いものほど上。

```
┌───────────────────────┐ y=0
│  LIFE  ♥♥♥♥♥♥         │ y=28   常設
│  BOMB  ●●●●●   [X]    │
│  浄化  ▓▓▓▓░░░░ 19%   │ y=196  常設
│  SCORE      12,340    │ y=288  常設
│  TIME      0:17.00    │ y=360  常設
│  COMBO        × 7     │ y=440  条件（コンボ2以上）
│  ● 連射         [V]   │ y=520  条件（モード2つ以上）
```

## 9. 文字（フォント刷新）

現状は Zen Kaku Gothic New（Regular/Bold/Black）＋ JetBrains Mono。問題は、内部解像度へ 0.3 倍で落ちるため `FontSmall=11` が実効 3.3px、`FontTiny=9` が 2.7px で、設計上の可読下限を割っていること。

**フォントファイルは変えない**（指揮官決定）。新規フォント導入は字形の統一・ライセンス・容量のコストに対して得るものが薄い。割り当てとサイズを整理する。

| 役割 | サイズ（設計） | 字間 | 行間 | フォント | 使う場所 |
|---|---|---|---|---|---|
| 数値（大） | 26 | +0.5 | — | Mono | SCORE、TIME の値 |
| 数値（中） | 18 | +0.5 | — | Mono | コンボ、残バー、浄化 % |
| セクション見出し | 15 | **+1.5** | — | ZenBold | LIFE / BOMB / SCORE / TIME / 浄化 |
| 本文・セリフ | **17**（現15） | 0 | **1.55倍** | Zen | 会話バー本文、ナレ |
| 話者名 | 19 | +0.5 | — | ZenBold | 会話バーの話者 |
| 小ラベル | **13**（現11を廃止） | +0.5 | — | ZenBold | キーバッジ、炎上の内訳 |
| 極小（9） | **廃止** | — | — | — | 用途自体が消える |

要点: `FontTiny` を廃止して実効 2.7px を画面に出さない。短い英字ラベルには字間 +1.5（`Hud.cs:1829 DrawTracked` が既にある）。会話本文を 15→17・行間 1.55（2行固定なのでページが増えるだけ）。ラベルは Mono → ZenBold、数値だけ Mono に残す。`UiKit` に `TextStyle`（Font/Size/Tracking/Leading）を導入し、画面ごとのサイズ直書きを断つ。

### 背景に流れるコメントのフォント

ユーザー指摘「背景の流れているコメントのフォントがださい」。対象は `StageImagery.cs` が `UiKit.Zen` で描く投稿カードの文字。読ませない文字なので、Regular のままサイズと濃さで押すのではなく、**字間を広げて濃さを落とす**（α 0.35〜0.5、字間 +1.0）。それでも足りなければ、背景カードのデザイン刷新（別タスク）と合わせて Light ウェイトの導入を検討する。

## 10. 実装の順序

各段の終わりで実機と自動プレイを通す。

1. **第1段: 削除だけ先にやる**（S〜M）。器を先に作ると情報が戻るので順序は絶対にこちら先。常設 HUD が 11個 → 5個 になる。
2. **第2段: `Field` 静的クラスを新設し、座標の参照を1か所に集める**（S）。**`Left = 0f` のまま全置換し、挙動が変わらないことを確認**してから次へ。これが最も安全。
3. **第3段: `Field.Left = 120` に変え、パネル枠を描く**（M）。壊れやすいのは弾幕の対称軸、安置の配置、前のめり進行の体感。
4. **第4段: UI 要素の移設**（M）。ボスバー・スペルカード・字幕・会話バーを中心へ、カットインを右袖へ、`TopLeftFade` を削除。
5. **第5段: 文字**（S〜M）。`TextStyle` 導入とサイズ置換。会話本文と折り返し幅はセットで直す。
6. **第6段: スクショと wiki の撮り直し**（M・機械作業）。`--shot` は `build/shots` を消すので `build/shots_gallery/` からの復元手順を守る。

総合規模は **M**（第2段の2段構えで L から落ちる）。実装より第3段の弾幕検証が本体。

## 11. 指揮官の決定（査定への回答）

1. **回避よけはやさしさぶんだけ削除**。スコア・インプレ・コンボ猶予は残す。
2. **サイドパネル幅は 112 内部px（設計 373px）で着手**。`Field.Left` の1定数なので実機を見て調整する。
3. **フォントファイルは維持**（Zen Kaku Gothic New / JetBrains Mono）。割り当てとサイズだけ刷新する。背景のコメントは字間と濃さで先に直し、それでも足りなければウェイト追加を検討。

## 12. 触らないもの

`project.godot` の viewport、`Ripple.cs`（連鎖浄化は常時オン）、`Contamination` の値と全参照、`RunImpression`／`Impression`、`HeartsSaved`／`HeartGoal`、グレイズの当たり判定・閃光・SE、カットシーンと全メニュー画面、難易度倍率とボスHP方針。
