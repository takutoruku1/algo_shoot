- **`p2`（おはよう／きこえてる／うごいた）** — 迷い秒数と文字数を実測で受けに差し込む仕掛けが既に強く、【初】として F4 まで届く唯一の入口。触ると F4 が壊れる。

- **`s1_5`（宛先、ちがう／ぜったい／傘、忘れてる）** — 「傘、忘れてる」がこのゲームの選択肢の**お手本**。具体名詞・短い・選ぶと他が惜しい。
- **`s1_2`（べつに／きらいじゃない／置き傘、三本目）** — 「置き傘、三本目」が s1_5 の傘立てと噛み合っていて、雨のモチーフが一往復する。
- **`s3_2`（見えてる／ちゃんと見てる／同接、9）** — ミナが自分のことで一度だけ聞く場面。「同接、9」で外の数字と内の数え方を対置する構造が既に完成している。
- **`s3_5c`（見てる／ここにいる／見ています）** — 三件目がミナ自身の下書きで、敬体で書かれていることにしか手がかりがない。気づいた人だけが不意打ちを食らう。本作で最も上手い選択肢。
- **`s3_7`（つづけて／むりしないで）** — ミナが「光が二割濁っています」と申告した直後の2択。どちらも正しく、どちらも何かを引き受ける。既に条件を満たしている。

- **`e6`（また来る／ありがとう）** — 迷い秒数を P2 と比較する対句、`NameRoute` を名前に触れずに回収する `nameEcho`、「いってらっしゃいませ、ご主人様」の反転。作品の締めくくりとして仕上がっている。

## 第2部: 提案（未実装）

### A. 死にデータの読み手を作る

#### A-1. `ScatteredWords` — 散った言葉の墓場を、ハブの一画面にする

現状: `GameManager.ScatteredWords`（`src/GameManager.cs:551`）は全選択の「選ばれなかった候補」を出た順に貯め、セーブにも載っている。`ChoiceEffects.PriorityScattered()`（`src/ChoiceEffects.cs:47`）まで書かれているのに**呼び出し元がゼロ**。プレイヤーは一度もこのリストを見ない。

提案: ハブのスマホに「下書き」アプリを1つ増やし、開くと**散った言葉だけ**が時系列に並ぶ。送った言葉は載せない。ミナは開いた回数を数えるだけで、中身には触れない。

- 1件目を開いたときだけミナが一行: 「……それは、送られなかったほうです。……こちらで、預かっています。」
- 2周目以降、前周の分は薄く表示して「前回のぶん」と分ける。
- 件数が20を超えたら、ミナが数だけ言う: 「……二十一件。……棚が、そろそろ。」

効き方: プレイヤーが「自分が何を手放してきたか」を**任意のタイミングで**見返せる。ゲーム側からは一度も見せない（押しつけない）のが肝。

#### A-2. `PriorityScattered()` を F4 の悲鳴の弾に流す

`ChoiceEffects.cs:13` のコメントは「Final（F4 の悲鳴に必ず混ざる語）… PriorityScattered」と設計意図を明記している。実装は関数まであって未接続。

提案: F4 の直前（`Final.cs` phase 0 の3.2秒）または選択提示中に、**プレイヤー自身が散らした言葉**を背景に降らせる。`PostBullets` の語彙プールではなく `PriorityScattered()` を引く。

- あかり面で散らした「傘、忘れてる」、こはる面で散らした「もう送れない相手」が、名前も出さずに画面を流れていく。
- 気づかない人には「ただの言葉の雨」。気づいた人には**自分が捨てた言葉だけが降っている**。
- ここで F4 の「（送らない）」を選ぶと、ミナの「それだけは、もう、散らせません」が別の意味になる。

#### A-3. `PressedTheQuestion` — フラグを生かすなら、レイ面の s3_7 に移す

`GameManager.PressedTheQuestion`（`:545`）はセーブ・ロード・リセットまで実装されているが、立てる側（`StageKoharu.cs:741`）が到達不能なので**永久に false**。

二案:

1. **削除する** — 到達不能な機構に合わせてフラグごと落とす。セーブの `pressedQ` は互換のため読むだけ残す。
2. **s3_7 に引き継ぐ** — 「つづけて」を選んだ＝ミナの申告（光が二割濁っている）を聞いた上で続行させた、を `PressedTheQuestion` 相当のフラグとして記録し、エピローグ E5b のミナの一行を差し替える。
   - 続行させた側: 「……あのとき、つづけて、と言っていただきました。……おかげで、最後まで、行けました。」
   - 「むりしないで」側: 「……あのとき、止めてくださいましたね。……止まっても、着いたのですが。」
   - どちらも責めない。**選んだ側の記憶だけが返る**のが効き目。

### B. `s3_5c` の受け皿（E4 が存在しない問題）

`StageRei.cs:184` のコメントは「効果＝E4 の開示に一行（送られたか、散ったか）」と書いているが、**`Epilogue.cs` に E4 というフェーズが無い**（実在するのは PhGaze=E5b / PhEnd=E6 / E7 ロール）。設計だけ残って着地点が消えている。

提案: E4 を新設せず、**E5b の見上げる10行の中**へ1行差し込む。場所は `Epilogue.cs:213`「——できることは、数えることと、覚えていることだけ、ですが。」の直後。

- 「見ています」を選んだ（＝ミナの下書きに気づいた）場合:
  「……ひとつ、申し上げていませんでした。あの部屋で、わたくしの下書きも、一件ありました。」
  「……ご主人様が、送ってくださいました。……それだけ、記録に。」
- 気づかなかった／散らした場合:
  「……ひとつ、申し上げていませんでした。あの部屋で、わたくしの下書きも、一件ありました。」
  「……散りました。……自分で拾って、いまも持っています。」

効き方: レイ面の「気づいてよ」とミナの「気づいて、いただけましたか」が同じ面で重なっている構造（`StageRei.cs:224-228` のユーザー承認メモ）が、**エンディングまで到達する**。現状は面の中で閉じている。

### C. フレーバー選択に効果を1つずつ持たせる（軽い案）

第1部で文面は直したが、`p4` / `s1_4` / `s2_2` / `s2_4` は依然「その場の1〜2行しか変わらない」。既存の記録機構（`RecordChoice`）だけで足せる効果:

- **`p4`「見なかったことにする」** — 【濁】+0.01 を最初に一度だけ。プロローグで既に少し濁っている状態から始まる。タイトルの ver 表記の下あたりに出る `IdleTalk` が1行だけ変わる。
- **`s1_4`「いちばん上の、一件だけ」** — あかり戦のクリア後、ハブの再訪小話が「残りの十一件」に固定される。「……まだ、閉じたままです。……急ぎません。」
- **`s2_2`「電池、切れてる」** — こはる戦の改心後、こはるの台詞に一言増える。「……知ってたんだ。……うん、知ってた。」
- **`s2_4`「もう送れない相手」** — F4 の `FirstWord` フォールバックの優先順位を変える。【初】が空のときの "ミナ" ではなく、この選択を通ったプレイヤーには別の語が戻る。

いずれも分岐の構造（step 番号・選択肢の個数・`RecordChoice` の呼び方）を変えずに足せる。
