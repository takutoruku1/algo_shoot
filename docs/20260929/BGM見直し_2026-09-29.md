## 0. この監査の限界（先に明記する）

**担当（AI）は音を聴いていない。聴けない。** したがって「この曲はこの場面に合う／合わない」を耳で判定したものは
この文書に一つも無い。判定に使った材料は次の3つだけである。

1. `BGM/acquisition_list.md`（430行）と `BGM/candidates.md`（395行）に**文章で記録された曲の性格**
   （タグ・楽器・BPM・LUFS・LRA・spectral centroid・起伏曲線・尺・採用理由・対抗馬）
2. `src/Audio.cs` の実際の割り当てと、その呼び出し元（`file:line`）
3. `wiki/`（2026-09-28 に実装と突き合わせ済み）が書く「いまその場面で何が起きているか」

**「曲の善し悪し」は判定していない。判定したのは「配線として穴が無いか」「記録された性格と
場面の中身が食い違っていないか」の2点だけ。** 最終判断は作者の耳に委ねる。

## 2. 見つけたちぐはぐ（根拠つき）

### ① 【最大の欠陥】FINAL の道中 67.7 秒が丸ごと無音だった

- **事実**: `src/StageMina.cs:_Ready` が `StopMusic(fade:1.2f)` で曲を落としてから、次に音楽が立つのは
  `src/BossMina.cs:184` の `Music(BgmBossMina)` である。その間にある `Step_Route`（残響の三波）に
  音楽の呼び出しが**1行も無かった**。
- **なぜ穴なのか**: この無音は元々「F1 導入（タイトルカード＋壊れたミナの声）を沈黙に委ねる」意図だった
  （`StageMina.cs` の当該コメント）。当時の道中は残響3体・**実測 6.7 秒**。2026-09-27 の
  「MINA の道中戦を長くして」で三波66体になり、`tools/FinalRouteQa` の実測で
  **Normal 67.7 秒／Lunatic 47.3 秒**（本タスクで再実測）。
  つまり**意図した余白が10倍に引き伸ばされ、66体と撃ち合う1分強が無音になっていた**。
  mitsuda style §7 の「無音は最強の音」は**決定打の直前に置く**話であって、戦闘区間を
  無音にする話ではない（§10「鳴らしすぎ」の裏返しで「鳴らなさすぎ」）。
- **判定**: 意図ではなく、尺変更の巻き添えで開いた穴。**修正した**（§3-①）。

### ② 【ルナティック】ボステーマが最後までこもったまま開かない

- **事実**: ボステーマは「投稿の札を割った数（depth 0..5）」でローパスと音量が開く設計になっている。
  - こはる／レイ／ミナ: `src/Audio.Posts.cs` `ApplyPostMix()` … cutoff `Lerp(2400, 18000, depth²)`／bus `Lerp(-4.5, 0, depth)`
  - あかり: `src/Audio.Akari.cs` `TickAkariMusic()` … cutoff `Lerp(1800, 16500, depth²)`／bus `Lerp(-5, 0, depth)`
- **ルナティックでは札の割り込みごと畳んでいる**:
  - `src/BossPostSequence.cs:34` … `if (GameManager.LunaticActive) sequence._thresholds = Array.Empty<float>();`
    → `Count` が永久に 0 → `ResumeMusic()` が `StartPostMusic(id, 0)` を呼ぶ → **depth 0 で固定**
  - `src/BossAkari.cs:205`（修正前） … `Audio.Instance?.StartAkariMusic(0);` の **0 決め打ち**。
    ルナティックでは直前の行で `_postsBroken = PostThresholds.Length`（＝5）にしてあるのに、
    音楽へ渡す深度だけ 0 のままだった → `BreakPost` も走らないので **depth 0 で固定**
- **結果**: ルナティックの4ボス戦すべてで、曲が **1800〜2400Hz のローパス＋-4.5〜-5dB のまま**
  最後まで鳴る。ルナティックは「物語の演出を全部切った純粋シューティング」なので、
  曲が晴れる瞬間が一度も来ない＝**ご褒美の演出だけが消えて、罰（こもり）だけが残っていた**。
- **判定**: ルナティック化（2026-09-26）の副作用。**修正した**（§3-②）。

### ③ FINAL でゲームオーバーから復帰すると、別の面の道中曲が蘇り得た

- **事実**: `Audio.CurrentStageId` は `GameManager.BeginStageRun(id)` でしか設定されないが、
  **`src/MinaRoot.cs` は `BeginStageRun` を呼ばない**（FINAL は面の頭を無音で始めるため）。
  一方 `src/MinaRoot.cs:138` は `GameManager.ClearGameOverChoice(Hud)` を呼び、これは
  `restoreMusic:true` 経路で `Audio.ResumeStageMusic()` → `StageBgm(CurrentStageId)` を引く。
  FINAL に入った時点の `CurrentStageId` は**直前に遊んだ面（"rei" 等）のまま**なので、
  FINAL で残機が戻った瞬間に**レイの道中曲が鳴り出す**（一度もリセットしていなければ `""` →
  合成 `BgmStage`）。
- **判定**: 配線漏れ。**修正した**（§3-③）。

### ⑧ タイトル／プロローグの絵と曲の相性（記録上の突き合わせ）

**注意: 絵は見たが、曲は聴いていない。** 以下は「記録された曲の性格」と「画像として見た絵」の突き合わせ。

- **タイトル**: v2 は「屋上・夕暮れの空・街の灯り」で、**曲名「見上げた空」と絵が直結**していた。
  v3 は「タイムラインの層の中で手を差し出し、投稿から金の糸で下書きが引き出される」＝**空が無くなった**。
  ただし `BGM/candidates.md` ⑭ に記録された採用理由は
  「曲名がそのまま本作の**所作**（エピローグ E5b『見上げる』）。タイトルで無害に置いた曲名が終盤の場面と響き合う
  ＝旋律ではなく**言葉での伏線**」であり、**絵との一致は選定理由に入っていない**。
  さらに記録上の性格（しみじみ・ニューエイジ／centroid 1277Hz＝丸い／0→80秒でゆっくり満ちる）は
  「冷たい層の中を一本の温かい金の線が通る」という v3 の構図と食い違わない。
  → **据え置きを推奨**。ここを別曲にすると E5b への言葉の伏線が切れる（回収先が消える）。
- **プロローグ**: `timeline_depth_v2` は冷たい蛍光色の、奥へ無限に続く投稿カードの回廊。
  `bgm_prologue`「オーヴⅡ」の採用理由は「Prologue は**テキストが主役**。旋律のある曲を敷くと文字と競合する。
  アンビエントで**世界の底の音**だけを鳴らすのが正しい。『オーヴ＝光の球』は起動時のコードレイン／
  **タイムラインの無機質さ**に合う」。→ **新しい絵のほうが採用理由と直接一致している**。**据え置き**。

## 4. 直せなかったもの＝発注仕様（作曲・調達が要る）

**作曲も音声生成もこの環境にはできない。** 以下は「こういう曲が要る」という発注仕様。
いずれも既存パイプライン（`BGM/` にマスター → ffmpeg で -17.7 LUFS 前後へ → `audio/bgm_*.ogg`・
`import loop=true`）に乗せれば**コード変更なしで差し替わる**ように器を用意してある。

### A. `audio/bgm_final_route.ogg` — FINAL 道中の専用曲（優先度: 高）

いまは Frozen Forest の再配置で埋めてあるが、本来は専用曲が要る枠。

- **情緒**: ミナの内側。三人ぶんの穢れを抱えきって「満ちた」場所を、あなたの光が一本だけ通っていく。
  残響（ミナ自身の声の反響）と撃ち合うが、**敵意ではない**。悲鳴ではなく空虚。
- **音楽仕様**: BPM 90–110 ／ 短調 or 無調寄り ／ **ガラス・氷・グロッケン系の澄んだ音色を核**に
  （ミナのライトモチーフ）＋低音の持続。旋律は立てすぎない（**LRA 3 以下の平坦さ**が望ましい）。
  盛り上がりの山は要らない（山は直後の Dramatic5 が持つ）。
- **尺・ループ**: **75 秒以上**（Normal の道中実測 67.7 秒を1周で賄う）。完全ループ前提。
- **ラウドネス**: -14 〜 -17 LUFS（`MusicTargetDb` が -10dB を乗せる戦闘曲側の帯）。
- **ライセンス**: 商用可・**改変可（必須）**・ゲーム組込可。クレジット義務の有無を `acquisition_list.md` §6 に記録すること。
- **置くだけで鳴る**: `LoadBgmFinalRoute()` が自動的に専用曲を優先する。置いた時点で
  `bgm_boss_hikage` との共用が解消され、QA（§5）の重複チェックもそちらへ切り替わる。

### B. `audio/bgm_final_resolve.ogg` — ボーカル入りの挿入歌（優先度: 中・据え置き継続）

- 2026-07-20 からの積み残し。現行は自前生成インスト（Morning_Light_on_Glass 由来）。
- **情緒**: 「返事は、ありませんでした。」の直後。喪失と赦しと朝の光。作中唯一の「歌」。
- **仕様**: 女性ボーカルの静かなバラード／ピアノ+弦の最小伴奏／長調圏（直後の `BgmMenu` へ橋渡すため）／BPM 60–80。
- **注意**: 歌詞がシーン（喪失→帰還）と衝突しないこと。強すぎるならインスト維持が安全。
- 結線・キュー・音量は完成済み。**ファイルを置き換えるだけ**。

### C. ローディング画面のエラー時 UI 効果音（優先度: 低・SE）

- `src/LoadingScreen.cs` は Audio を一切呼ばない。読み込み失敗時の「やりなおす／タイトル」の
  カーソル移動・決定に音が無く、他の全メニュー（`PlayUiMove` / `PlayUiSelect` / `PlayUiCancel`）と手触りが揃わない。
- 既存の合成 SE をそのまま使えるので**新規音源は不要**。本タスクは BGM の監査なので手を付けていない。

### D.（任意）FINAL 道中の汚染連動を有効にするか

- §3-① の末尾のとおり 1 行で切り替わる。**800Hz まで落ちる設定が未試聴**なので、
  作者が実機で聴いて判断する項目として残す。
